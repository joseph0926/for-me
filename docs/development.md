# 개발 절차

작업마다 만들 동작을 정하고, 구현한 뒤 검사 결과를 남깁니다. 이 저장소의 하네스는 개발 절차, 작업 규칙, QA 절차와 이슈 처리 기준으로 구성합니다. QA는 앱을 직접 조작해 기대한 동작인지 확인하는 검증입니다.

## 현재 상태

- 루트의 Gradle 프로젝트와 `app` 모듈에 Android 시제품을 구현했습니다.
- 코드 검사, 테스트, 앱 빌드 명령을 연결했습니다.
- 가상 기기에서 ADB로 파일 선택, 재생 조작과 이어보기를 확인했습니다. 발견한 문제는 [QA 이슈](qa-issues.md)에 남깁니다.
- 실제 기기에서 재생을 확인하지 않았습니다.

## 개발 환경

- JDK 17
- Android SDK Platform 36
- Android SDK Build-Tools 36.0.0
- Gradle 8.14.3: 저장소의 `gradlew` 사용

Android Studio에서 저장소 루트를 엽니다. Gradle 실행에 JDK 17을 사용합니다. `gradle/gradle-daemon-jvm.properties`도 17로 고정하며 JDK 자동 설치는 사용하지 않습니다.

SDK 위치는 `ANDROID_HOME` 또는 Git에서 제외한 `local.properties`의 `sdk.dir`로 지정합니다. 전역 Gradle 설치는 필요하지 않습니다.

앱 식별자는 `dev.forme.video`입니다. 최소 Android 버전은 8.0(API 26)이며, 빌드와 대상 SDK는 36입니다. `arm64-v8a`와 `x86_64`용 라이브러리를 포함합니다.

## 작업 순서

1. 이번에 만들 동작과 완료 기준을 정합니다. 범위가 바뀌면 동영상 앱 문서를 먼저 고칩니다.
2. 해당 동작을 구현합니다. 기술 선택이 바뀌면 이유를 기술 조사 문서에 남깁니다.
3. 변경한 동작에 필요한 자동 검사를 실행합니다.
4. 실제 재생이나 파일 접근, 데이터 보존에 영향을 주면 [QA 절차](qa.md)에 따라 앱을 조작합니다. 가상 기기 결과와 실제 기기 결과를 구분합니다.
5. 검증 기록에 결과와 미검증 항목을 남기고, 발견한 문제는 [이슈 처리 기준](qa-issues.md#처리-기준)에 따라 분류합니다.
6. 승인된 작업 범위의 결함은 수정 후 같은 조건에서 다시 확인합니다. 수정 권한이 없거나 검증 환경이 없으면 이슈와 남은 조치를 기록하고 완료 범위를 제한합니다.

필요한 검사가 통과하면 작업을 마칩니다. 새 변경이나 실패, 구체적인 우려가 생겼을 때만 검사 범위를 넓힙니다.

## 자동 검사

저장소 루트에서 실행합니다.

```bash
./gradlew --no-daemon :app:lintDebug :app:testDebugUnitTest :app:assembleDebug :app:assembleRelease
```

- 코드 검사: Android Lint로 오류와 플랫폼 사용 문제를 확인합니다.
- 테스트: 재생 위치 저장과 복구 등 변경한 동작을 확인합니다.
- 앱 빌드: 디버그 APK와 서명하지 않은 릴리스 APK를 만듭니다. APK는 Android 앱 설치 파일입니다.

Lint 경고는 오류로 처리합니다. 새 라이브러리나 빌드 도구 버전이 나왔다는 알림 3종은 정보로 표시하며, 업데이트는 호환성을 확인한 뒤 반영합니다.

기기에 설치할 파일은 `app/build/outputs/apk/debug/app-debug.apk`입니다. 릴리스 파일은 `app/build/outputs/apk/release/app-release-unsigned.apk`이며, 서명과 외부 배포는 수행하지 않습니다.

코드 검사 보고서는 `app/build/reports/lint-results-debug.html`, 테스트 보고서는 `app/build/reports/tests/testDebugUnitTest/index.html`에 생성됩니다.

테스트는 입력과 기대하는 결과를 기준으로 작성합니다. 재생기를 흉내 낸 테스트는 앱의 상태 처리를 확인하는 데 쓰고, libVLC의 실제 재생은 기기에서 확인합니다.

현재 로컬 테스트는 재생 위치 처리와 Room 데이터 보존, 파일 접근 실패를 검사합니다. Room과 파일 접근 테스트는 Android 동작을 개발 머신에서 재현하는 Robolectric을 사용합니다. 실제 시스템 권한과 기기 동작을 확인하는 검사는 아닙니다.

Room의 저장 구조는 `app/schemas`에 남깁니다. 구조를 바꿀 때는 기존 기록을 보존하는 변환과 검사를 함께 추가합니다.

재생 중에는 약 2초마다 위치를 저장하고, 일시정지와 화면 종료 때도 저장합니다. 강제 종료나 전원 차단 직전의 위치까지 저장된다고 보장하지 않습니다. 실제 업데이트 검증에는 같은 서명 키를 사용해야 합니다.

빌드나 CI, 릴리스 구성을 바꾸면 기존 생성물이 없는 임시 사본에서 같은 명령과 순서로 검증합니다. CI는 변경 시 검사를 자동 실행하는 환경입니다. 릴리스 명령이 있으면 외부 게시 없이 모의 실행하고, 실행하지 못한 단계는 남깁니다.

## 기기 검증

가상 기기에서는 기본 사용 흐름을 먼저 확인합니다. 실제 기기 검증은 갤럭시 S25에서 시작하고 두 번째 기기로 넓힙니다. 정확한 모델명과 Android 버전은 실행할 때 기록합니다. 실제 기기 연결을 미룬 작업에서는 해당 검증을 미검증으로 남깁니다.

기본 순서는 다음과 같습니다.

설치 → 영상 재생 → 앱 종료 → 이어보기 → 업데이트 설치 → 이어보기 재확인

- 업데이트는 이전 앱을 지우지 않고 같은 앱 식별자와 서명으로 설치합니다.
- 업데이트 전 버전에서 저장한 재생 위치와 파일 접근이 유지되는지 확인합니다.
- 기기 재시작, 권한 취소, 파일 이동과 삭제도 해당 변경에 맞춰 확인합니다.
- 설치한 APK와 검사에 사용한 파일을 식별할 수 있게 기록합니다.

조작과 증거 수집은 [QA 절차](qa.md), 세부 항목과 기록 형식은 [검증 기록](video-app-verification.md)을 사용합니다. 수정한 이슈는 새 APK를 설치해 재현 조건과 영향받는 동작을 다시 확인한 뒤 완료합니다.

## 구성을 늘리는 기준

처음에는 한 작업씩 구현하고 기존 빌드 도구로 검사합니다. 같은 실패나 수작업이 반복될 때 추가 자동화를 검토합니다. 별도 하네스 프로그램, 자동 훅, 상시 다중 에이전트 구성은 현재 도입하지 않습니다.
