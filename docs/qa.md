# QA 절차

앱을 직접 조작하고 화면과 동작을 확인합니다. 자동 검사의 통과 여부와 기기에서 확인한 결과는 따로 기록합니다.

이 문서는 모든 앱에 공통인 절차입니다. 조작 도구, 명령 예시와 확인 항목은 각 앱의 `apps/<앱>/docs/qa.md`에 있습니다.

## 실행 전

1. 이번 작업의 기대 동작과 확인할 항목을 정합니다. 해당 앱의 QA 이슈(`apps/<앱>/docs/qa-issues.md`)에서 관련 재현 조건도 확인합니다.
2. 대상 기기나 컴퓨터의 모델, 운영체제와 버전, 가상 환경 여부를 확인합니다. 화면 배율과 모니터 구성처럼 결과에 영향을 주는 환경도 기록합니다.
3. 검사할 앱 버전과 설치 파일의 SHA-256, 코드 상태를 기록합니다. 설치된 앱과 로컬 설치 파일이 같은 빌드인지 확인하고, 다르면 검사한 쪽을 기준으로 남깁니다.
4. 검사에 쓰는 입력 파일의 식별값과 형식을 기록합니다. 모르는 값은 미확인으로 둡니다.
5. 실행마다 별도의 증거 폴더를 앱 폴더 안의 Git에서 제외되는 빌드 결과 아래에 만듭니다. 이전 실행의 화면과 로그를 덮어쓰지 않습니다.

사용자의 원본 파일을 변경하지 않습니다. 파일 이동, 삭제나 손상 대응을 확인할 때는 해당 검사용 복사본을 사용합니다. 기존 기록과 파일 접근 권한을 보존해야 하는 검사는 앱 삭제나 데이터 초기화 없이 진행합니다.

설치형 macOS 앱은 QA 시작과 종료 시 [설치본 관리 절차](development.md#macos-앱-설치본-관리)에 따라 앱 검색 결과, 설치 경로와 실행 파일의 SHA-256을 확인합니다.

## 조작 방법

앱마다 정한 조작 도구를 기본으로 사용합니다. 사용자가 컴퓨터 사용 도구로 조작하도록 지정하면 그 방식을 따르고, 실패하면 확인한 범위와 도구 오류를 알립니다. 도구 오류를 앱 결함으로 판정하지 않습니다.

조작은 다음 순서로 반복합니다.

1. 현재 화면과 화면 요소를 읽습니다.
2. 확인한 버튼이나 위치를 한 단계 조작합니다.
3. 원하는 상태가 나타났는지 다시 확인합니다.
4. 기대 결과와 실제 결과, 증거 파일을 기록합니다.

회전, 창 전환이나 화면 크기 변경 후에는 좌표를 다시 구합니다. 이전 화면의 좌표를 그대로 누르지 않습니다.

조작 직후 정해진 시간만 기다리고 성공으로 처리하지 않습니다. 기대한 상태 변화를 확인한 뒤 다음 조작으로 넘어갑니다. 제한 시간 안에 준비되지 않으면 대기 시간과 상태를 기록합니다. 준비 중 조작을 일부러 검사하려는 경우에는 그 조건을 따로 남깁니다.

Windows에서 명령 예시는 Git Bash에서 실행합니다. PowerShell 5.1의 `>` 리디렉션은 출력을 텍스트로 바꾸므로 화면 캡처 같은 바이너리 출력이 깨집니다.

## 확인 항목

앱마다 확인할 항목은 `apps/<앱>/docs/qa.md`에 있습니다. 변경과 관련된 항목을 골라 실행합니다. 한 번의 QA에서 모든 항목을 수행할 필요는 없지만, 실행하지 않은 항목을 통과로 표시하지 않습니다.

## 증거와 판정

각 항목을 통과, 실패, 미검증으로 기록합니다. 미검증은 구현 없음, 샘플 없음, 기기 없음, 도구 장애처럼 이유를 적습니다. 실패는 해당 앱의 QA 이슈에 연결하고, 관련 없는 검사에는 계속 진행할 수 있습니다. 데이터 손상 위험이 있으면 해당 경로의 검사를 중단합니다.

- 화면 캡처와 화면 구조 자료는 동작별 순서와 이름을 붙입니다. 파일명은 증거를 찾는 용도이며 통과 판정을 대신하지 않습니다.
- 서로 다른 시점에 수집한 자료는 수집 순서를 고려해 비교합니다.
- 로그는 대상 앱과 검사 시간 범위로 한정합니다. 종료나 충돌로 프로세스가 바뀌면 이전 프로세스의 로그도 확보합니다. 오류 문구 하나나 오류가 없는 로그만으로 성공과 실패를 판단하지 않습니다.
- 원본 보존을 검사할 때는 사용 전후 파일 해시를 비교합니다. 검사 중 바꾼 기기나 운영체제 설정은 원래 값으로 되돌립니다.
- 증거 폴더는 Git에서 제외되는 로컬 빌드 결과입니다. 빌드 정리로 사라질 수 있으므로 재현 절차, 기대값, 실제값과 빌드 식별값은 문서에도 남깁니다. 외부 공유 시에는 별도 승인 범위와 개인 정보 포함 여부를 확인합니다.

실행이 끝나면 해당 앱의 검증 기록(`apps/<앱>/docs/verification.md`)에 결과를 추가하고, 이슈의 현재 상태를 갱신합니다. 수정 후 재검증은 새 실행으로 남기며 최초 실패 기록을 성공으로 바꾸지 않습니다.
