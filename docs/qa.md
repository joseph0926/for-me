# QA 절차

앱을 직접 조작하고 화면과 동작을 확인합니다. 자동 검사의 통과 여부와 기기에서 확인한 결과는 따로 기록합니다.

## 실행 전

1. 이번 작업의 기대 동작과 확인할 항목을 정합니다. [기존 이슈](qa-issues.md)에서 관련 재현 조건도 확인합니다.
2. 대상 기기의 식별자, 모델, Android 버전과 가상 기기 여부를 확인합니다. 연결된 기기가 여러 개면 ADB 명령마다 대상을 지정합니다.
3. 검사할 앱 버전과 APK의 SHA-256, 코드 상태를 기록합니다. 설치된 앱과 로컬 APK가 같은 빌드인지 확인하고, 다르면 검사한 쪽을 기준으로 남깁니다.
4. 샘플의 식별값, 파일 형식, 영상과 음성 압축 방식, 자막, 길이와 해상도를 기록합니다. 모르는 값은 미확인으로 둡니다. 도구가 있으면 `ffprobe`로 확인합니다.
5. 실행마다 별도의 증거 폴더를 만듭니다. 예: `app/build/reports/qa/20261114-173000/`. 이전 실행의 화면과 로그를 덮어쓰지 않습니다.

영상과 자막 원본을 변경하지 않습니다. 파일 이동, 삭제나 손상 대응을 확인할 때는 해당 검사용 복사본을 사용합니다. 기존 재생 기록과 파일 접근 권한을 보존해야 하는 검사는 앱 삭제나 데이터 초기화 없이 진행합니다.

## 조작 방법

이 저장소의 Android QA는 ADB를 기본으로 사용합니다. ADB는 개발 머신에서 가상 기기나 Android 기기에 명령을 보내는 도구입니다. Android Studio는 빌드, 기기 실행과 화면 확인에 사용합니다. 사용자가 컴퓨터 사용 도구로 조작하도록 지정하면 그 방식을 따르고, 실패하면 확인한 범위와 도구 오류를 알립니다. 도구 오류를 앱 결함으로 판정하지 않습니다.

조작은 다음 순서로 반복합니다.

1. 현재 화면과 화면 요소를 읽습니다.
2. 확인한 버튼이나 위치를 한 단계 조작합니다.
3. 원하는 상태가 나타났는지 다시 확인합니다.
4. 기대 결과와 실제 결과, 증거 파일을 기록합니다.

화면 요소는 `uiautomator dump`로 가져오고, 실제 표시는 `screencap`으로 확인합니다. 회전, 파일 선택기 전환이나 화면 크기 변경 후에는 좌표를 다시 구합니다. 이전 화면의 좌표를 그대로 누르지 않습니다.

재생 버튼을 누른 직후 정해진 시간만 기다리고 성공으로 처리하지 않습니다. 재생 준비, 시간 진행과 영상 변화를 확인한 뒤 다음 조작으로 넘어갑니다. 제한 시간 안에 준비되지 않으면 대기 시간과 상태를 기록합니다. 이른 일시정지처럼 준비 중 조작을 검사하려는 경우에는 그 조건을 따로 남깁니다.

### ADB 명령 예시

다음은 macOS에서 SDK가 기본 경로에 있는 경우의 예시입니다. 기기 식별자는 `devices -l` 결과에서 고르고, 증거 경로는 실행마다 새로 정합니다. 아래 기기와 경로를 그대로 반복 사용하지 않습니다.

```bash
ADB="$HOME/Library/Android/sdk/platform-tools/adb"
"$ADB" devices -l
QA_SERIAL="emulator-5554"
QA_DIR="app/build/reports/qa/20261114-173000"
mkdir -p "$QA_DIR"

"$ADB" -s "$QA_SERIAL" shell getprop ro.build.version.release
"$ADB" -s "$QA_SERIAL" shell getprop ro.build.version.sdk
"$ADB" -s "$QA_SERIAL" shell wm size
"$ADB" -s "$QA_SERIAL" shell pm path dev.forme.video

"$ADB" -s "$QA_SERIAL" shell uiautomator dump /sdcard/for-me-qa.xml
"$ADB" -s "$QA_SERIAL" pull /sdcard/for-me-qa.xml "$QA_DIR/01-before.xml"
"$ADB" -s "$QA_SERIAL" exec-out screencap -p > "$QA_DIR/01-before.png"
```

현재 화면 요소에서 확인한 좌표를 `shell input tap X Y`에 전달합니다.

`shell input keyevent 4`는 뒤로 가기, `shell input keyevent 3`은 홈으로 이동합니다. 강제 종료를 검사할 때는 `shell am force-stop dev.forme.video`, 다시 실행할 때는 `shell am start -W -n dev.forme.video/.MainActivity`를 사용합니다. 종료 방법마다 저장 시점이 다를 수 있으므로 일반 닫기와 강제 종료를 구분해 기록합니다.

화면 회전은 먼저 `shell cmd window user-rotation`으로 현재 설정을 기록합니다. `shell cmd window user-rotation lock 1`은 가로, `lock 0`은 세로 방향을 고정합니다. 검사 후에는 기록한 설정을 복원합니다. 기존 설정이 `free`인 경우에만 `shell cmd window user-rotation free`로 되돌립니다.

덮어 설치는 같은 앱 식별자와 서명 키를 가진 APK에 `install -r`을 사용합니다. 테스트 전용 APK로 확인되거나 `INSTALL_FAILED_TEST_ONLY`가 나오면 `install -r -t`를 사용합니다. 서명이나 버전 문제로 설치가 거절되면 원인을 기록하고, 앱 삭제로 우회하지 않습니다.

## 확인 순서

변경과 관련된 항목을 골라 실행합니다. 한 번의 QA에서 아래 항목을 모두 수행할 필요는 없지만, 실행하지 않은 항목을 통과로 표시하지 않습니다.

- 파일 선택과 취소: 시스템 선택기로 샘플을 열고, 취소 시 기존 화면과 기록이 유지되는지 확인합니다.
- 재생과 조작: 시간과 영상의 변화를 확인하고, 일시정지 동안 위치와 장면이 유지되는지 본 뒤 재개와 위치 이동을 확인합니다. 소리는 실제로 듣거나 출력 증거를 확보한 경우만 통과로 기록합니다.
- 화면 전환: 재생 중과 일시정지 상태를 각각 회전하고, 홈으로 이동했다 복귀합니다. 장면, 위치, 길이, 재생 의도와 조작 가능 상태를 확인합니다.
- 이어보기: 위치를 기록한 뒤 영상을 닫거나 앱을 종료합니다. 다시 실행하고 최근 영상을 열어 저장한 위치에서 재생되는지 확인합니다. 기록이 목록에 남는 것만으로 통과하지 않습니다.
- 업데이트: 설치 전후 APK 식별값을 남기고 덮어 설치한 뒤 파일 접근과 이어보기를 확인합니다. 같은 APK 재설치와 다른 버전 업데이트, 저장 구조 변경 검증을 구분합니다.
- 실패 대응: 권한 거절과 취소, 검사용 파일의 이동과 삭제, 지원하지 않는 파일에서 안내와 재선택을 확인합니다.

전체 파일 지원과 실제 기기 호환성은 샘플 하나나 가상 기기 결과로 확정하지 않습니다. 자막, 소리, 재생 완료, 기기 재시작과 성능 등 세부 항목은 [검증 기록](video-app-verification.md#검사-항목)을 따릅니다.

## 증거와 판정

각 항목을 통과, 실패, 미검증으로 기록합니다. 미검증은 구현 없음, 샘플 없음, 기기 없음, 도구 장애처럼 이유를 적습니다. 실패는 [QA 이슈](qa-issues.md)에 연결하고, 관련 없는 검사에는 계속 진행할 수 있습니다. 데이터 손상 위험이 있으면 해당 경로의 검사를 중단합니다.

- 화면 PNG와 화면 요소 XML은 동작별 순서와 이름을 붙입니다. 파일명은 증거를 찾는 용도이며 통과 판정을 대신하지 않습니다.
- 두 자료는 서로 다른 시점에 수집됩니다. 재생 중 시간이 다르면 수집 순서를 고려하고, 정확한 상태 비교가 필요하면 일시정지한 뒤 수집합니다.
- 로그는 대상 앱과 검사 시간 범위로 한정합니다. 종료나 충돌로 프로세스가 바뀌면 이전 프로세스의 로그도 확보합니다. 오류 문구 하나나 오류가 없는 로그만으로 성공과 실패를 판단하지 않습니다.
- 원본 보존을 검사할 때는 재생 전후 파일 해시를 비교합니다. 검사 중 바꾼 회전 등 기기 설정은 원래 값으로 되돌립니다.
- 증거 폴더는 Git에서 제외되는 로컬 빌드 결과입니다. 빌드 정리로 사라질 수 있으므로 재현 절차, 기대값, 실제값과 빌드 식별값은 문서에도 남깁니다. 외부 공유 시에는 별도 승인 범위와 개인 정보 포함 여부를 확인합니다.

실행이 끝나면 [검증 기록](video-app-verification.md#실행-결과-작성)에 결과를 추가하고, 이슈의 현재 상태를 갱신합니다. 수정 후 재검증은 새 실행으로 남기며 최초 실패 기록을 성공으로 바꾸지 않습니다.
