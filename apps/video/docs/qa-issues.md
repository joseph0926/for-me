# QA 이슈

QA에서 발견한 문제의 현재 상태와 다음 조치를 관리합니다. 검사 당시의 결과와 증거는 [검증 기록](verification.md)에 남깁니다. 이슈를 해결해도 과거 실패 결과는 보존합니다.

## 처리 기준

### 발견과 분류

새 문제에는 `QA-001`부터 순서대로 번호를 붙입니다. 번호는 재사용하지 않습니다. 기존 문제와 같으면 해당 이슈에 재현 조건과 증거를 추가하고, 원인이 불확실하면 관련 이슈로 연결해 둡니다. 화면이 비슷하다는 이유만으로 같은 원인이라고 판단하지 않습니다.

기대 동작을 어기면 결함으로 기록합니다. 기대 동작 자체가 정해지지 않은 관찰은 확인 필요로 두고, 제품 동작을 정한 뒤 수정 여부를 판단합니다. 도구 연결 실패나 샘플 부족은 검증 기록의 미검증 사유로 남깁니다. 앱에 미친 영향이 확인되지 않은 로그 메시지만으로 결함을 만들지 않습니다.

우선순위는 사용자에게 미치는 영향으로 정합니다.

- 긴급: 원본 파일 손상, 저장 기록 유실, 승인하지 않은 접근처럼 데이터와 권한을 해치는 문제입니다. 해당 검사를 중단하고 증거를 보존하며 먼저 알립니다. 해결 전에는 영향을 받는 경로로 사용하거나 검사를 계속하지 않습니다.
- 높음: 파일을 열거나 재생하지 못함, 이어보기 실패, 핵심 조작 불가나 반복 충돌입니다. 영향을 받는 동작을 완료로 처리하지 않고, 그 사용 흐름에 새 기능을 추가하기 전에 수정합니다.
- 보통: 우회할 수 있는 표시 문제나 사용 불편입니다. 다음 수정 묶음에 포함합니다. 뒤로 미루면 이유와 다시 확인할 조건을 남깁니다.

### 수정 범위

QA나 조사만 요청받은 작업에서는 문제와 수정안을 기록하고 보고합니다. 이슈의 우선순위만으로 코드 수정 권한이 생기지는 않습니다.

기능 구현이나 버그 수정까지 승인된 작업에서는 그 범위의 결함을 수정하고 재검증까지 진행합니다. 받은 승인은 다시 묻지 않습니다. 관련 없는 기능 변경, 미정인 제품 동작, 새 의존성 도입이나 데이터 초기화 등 기존 승인 범위를 벗어나는 선택은 필요한 준비와 근거를 먼저 제시하고 결정받습니다.

### 상태와 완료

- 확인 필요: 관찰은 있지만 재현 조건이나 기대 동작을 더 확인해야 합니다. 다음 확인 방법을 적습니다.
- 수정 대기: 결함과 기대 동작이 확인됐으며 아직 수정하지 않았습니다.
- 수정 중: 승인된 범위에서 코드를 변경하고 있습니다.
- 재검증 대기: 수정은 했지만 해당 빌드에서 확인을 마치지 않았습니다. 기기가 없거나 검증이 막혀도 이 상태를 유지합니다.
- 완료: 수정 빌드로 원래 재현 조건과 영향받는 동작을 확인했습니다. 검증 날짜, APK 식별값과 결과 링크를 남깁니다.
- 보류: 지금 처리하지 않기로 한 문제입니다. 이유와 다시 살펴볼 조건을 적고, 사용에 영향을 주는 제한은 완료 보고에도 남깁니다.

수정하지 않아도 되는 관찰은 근거를 남기고 `완료 / 결함 아님`으로, 다른 이슈로 합친 항목은 `완료 / 중복 QA-번호`로 닫습니다. 재현하지 못했다는 이유만으로 결함 아님으로 처리하지 않습니다. 완료했던 문제가 다시 나타나면 기존 번호를 다시 열고 재발한 빌드와 조건을 추가합니다.

수정 후에는 먼저 원래 재현 순서를 실행하고, 수정이 영향을 주는 주변 동작을 확인합니다. 예를 들어 회전 문제라면 재생 중 회전과 일시정지 후 회전, 이어보기까지 확인합니다. 반복이나 간헐적 문제는 같은 조건에서 여러 번 확인하고 횟수를 기록합니다. 자동 검사는 원인에 맞춰 선택하며, 코드와 똑같은 계산을 반복하는 테스트를 추가하지 않습니다.

작업은 해당 완료 기준을 모두 통과했을 때 완료합니다. 열린 긴급 또는 높은 이슈가 그 기준에 영향을 주면 작업도 완료로 처리하지 않습니다. 관련 없는 기존 이슈 때문에 모든 작업을 막지는 않으며, 남은 문제와 미검증 범위를 함께 보고합니다.

## 기록 형식

간단한 문제는 아래 항목을 짧게 채웁니다. 장문의 로그나 같은 재현 설명을 반복하지 않고 검증 기록을 연결합니다.

```text
번호 / 제목:
상태 / 우선순위 / 발견일:
영향과 기대 동작:
재현 조건과 실제 결과:
환경과 빌드: 검증 기록 링크로 대신할 수 있음
증거:
원인: 확인된 사실과 추정 구분
다음 조치 또는 보류 이유와 재확인 조건:
수정과 재검증: 변경 내용, 검사한 빌드, 결과 링크
```

- 수정과 재검증: 2026-11-14, APK SHA-256 `4b508ecd63729d0e48e867f06ba06d568620fd1e321b32afe1f77bb818fc096a`. 일시정지 후 세로 → 가로 → 세로 회전을 두 파일에서 각각 두 번 확인했고 장면, 길이와 정지 상태가 유지됐습니다. 재생 중 회전과 저장 기록 유지도 확인했습니다. [수정 검증](verification.md#2026-11-14-회전과-상태-아이콘-수정-검증)에 주변 동작의 실패도 구분했습니다.

- 기대 동작: 재생 준비 중 일시정지하더라도 준비 완료 후에는 영상 길이와 가능한 조작을 표시해야 합니다.
- 환경과 증거: [2026-11-14 ADB QA](verification.md#2026-11-14-가상-기기-adb-qa)의 초기 일시정지 관찰과 `13-resume-after-stop`, `14-resume-settled`.
- 다음 조치: 준비 전후 일시정지 시점을 나눠 재현하고 QA-001과 같은 원인인지 확인합니다. 같으면 증거를 연결하고 중복으로 정리합니다.
- 수정과 재검증: 미수행.

### QA-005 재생바를 옮겨도 장면이 갱신되지 않음

- 상태: 완료. Android 14 가상 기기와 아래 샘플에서 확인한 범위입니다.
- 우선순위: 높음
- 발견일: 2026-11-14
- 영향과 기대 동작: 재생바의 시간과 실제 영상 장면이 일치해야 합니다. 사용자는 막대를 잡고 옮기는 중과 놓은 뒤 모두 문제를 보고했습니다.
- 최초 재현: 2026-11-14 회전 수정 APK에서 4K 샘플을 재생하고 일시정지한 뒤 회전하고 돌아왔습니다. 막대를 눌러 표시 시간을 `0:01`에서 `0:05`로 바꿨지만 장면은 같았습니다. 이어서 막대를 끄는 중과 놓은 뒤에도 장면이 같았습니다. 이후 저장 위치에서 다시 열었을 때 회전하기 전부터 영상이 회색으로 깨진 모습도 관찰했습니다.
- 비교: 시간이 표시된 640 × 360 샘플은 수정 전과 후 모두 일시정지 상태에서 막대를 놓으면 해당 장면으로 바뀌었습니다. 모든 파일에서 같은 실패가 난다고 판단하지 않습니다.
- 수정 전 코드: 끄는 중에는 표시값만 바꾸고, 손을 놓을 때만 재생기에 위치 이동을 요청합니다. 최초 조사에서는 놓은 뒤 장면이 멈추거나 깨지는 원인을 확정하지 않았습니다.
- 환경과 증거: [수정 검증](verification.md#2026-11-14-회전과-상태-아이콘-수정-검증)의 `42`부터 `45`, `50`부터 `52` 캡처와 `seek-frame-hashes.json`.
- 수정: 끄는 중에도 최신 위치로 이동하고, 손을 놓으면 마지막 위치를 바로 반영합니다. 같은 4K 파일에서 하드웨어 가속을 꺼도 실패했으나 내장 avformat 처리를 우선하면 장면이 정상으로 표시돼 해당 설정을 적용했습니다. 하드웨어 가속은 원래 설정을 유지합니다.
- 수정과 재검증: 2026-11-15, [재생바와 이어보기 수정 검증](verification.md#2026-11-15-재생바와-이어보기-수정-검증)의 최종 APK. 4K MP4에서 1초와 5초 이동을 회전 전후 반복했고, 시간 표시 샘플에서 끄는 중과 놓은 뒤의 장면을 확인했습니다.
- 남은 범위: 실제 기기의 성능과 다른 코덱, 음성과 자막은 미검증입니다.

### QA-006 재생이 끝난 뒤 위치 이동과 재개가 정상적이지 않음

- 상태: 완료. Android 14 가상 기기와 아래 샘플에서 확인한 범위입니다.
- 우선순위: 높음
- 발견일: 2026-11-14
- 영향과 기대 동작: 영상이 끝난 뒤에도 원하는 위치를 고르고 그 장면부터 재생할 수 있어야 합니다.
- 재현: 수정 전 APK에서 4K 샘플을 끝까지 재생한 뒤 막대를 눌러 `0:01`과 `0:05`로 옮겼습니다. 표시 시간만 바뀌고 장면은 같았으며, 재생을 시도한 뒤 재생 실패 안내가 나타났습니다.
