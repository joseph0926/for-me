# QA 이슈

QA에서 발견한 문제의 현재 상태와 다음 조치를 관리합니다. 검사 당시의 결과와 증거는 [검증 기록](verification.md)에 남깁니다. 이슈를 해결해도 과거 실패 결과는 보존합니다.

## 처리 기준

### 발견과 분류

새 문제에는 `QA-001`부터 순서대로 번호를 붙입니다. 번호는 재사용하지 않습니다. 기존 문제와 같으면 해당 이슈에 재현 조건과 증거를 추가하고, 원인이 불확실하면 관련 이슈로 연결해 둡니다. 화면이 비슷하다는 이유만으로 같은 원인이라고 판단하지 않습니다.

기대 동작을 어기면 결함으로 기록합니다. 기대 동작 자체가 정해지지 않은 관찰은 확인 필요로 두고, 제품 동작을 정한 뒤 수정 여부를 판단합니다. 도구 연결 실패나 샘플 부족은 검증 기록의 미검증 사유로 남깁니다. 앱에 미친 영향이 확인되지 않은 로그 메시지만으로 결함을 만들지 않습니다.

우선순위는 사용자에게 미치는 영향으로 정합니다.

- 긴급: 원본 파일 손상, 저장 기록 유실, 승인하지 않은 접근처럼 데이터와 권한을 해치는 문제입니다. 해당 검사를 중단하고 증거를 보존하며 먼저 알립니다. 해결 전에는 영향을 받는 경로로 사용하거나 검사를 계속하지 않습니다.
- 높음: 파일을 열거나 재생하지 못함, 이어보기 실패, 핵심 조작 불가나 반복 충돌입니다. 영향을 받는 동작을 완료로 처리하지 않고, 그 사용 흐름에 새 기능을 추가하기 전에 수정합니다.
- 보통: 우회할 수 있는 표시 문제나 사용 불편입니다. 다음 수정 묶음에 포함합니다. 뒤로 미루면 이유와 다시 확인할 조건을 남깁니다.

### 수정 범위

QA나 조사만 요청받은 작업에서는 문제와 수정안을 기록하고 보고합니다. 이슈의 우선순위만으로 코드 수정 권한이 생기지는 않습니다.

기능 구현이나 버그 수정까지 승인된 작업에서는 그 범위의 결함을 수정하고 재검증까지 진행합니다. 받은 승인은 다시 묻지 않습니다. 관련 없는 기능 변경, 미정인 제품 동작, 새 의존성 도입이나 데이터 초기화 등 기존 승인 범위를 벗어나는 선택은 필요한 준비와 근거를 먼저 제시하고 결정받습니다.

### 상태와 완료

- 확인 필요: 관찰은 있지만 재현 조건이나 기대 동작을 더 확인해야 합니다. 다음 확인 방법을 적습니다.
- 수정 대기: 결함과 기대 동작이 확인됐으며 아직 수정하지 않았습니다.
- 수정 중: 승인된 범위에서 코드를 변경하고 있습니다.
- 재검증 대기: 수정은 했지만 해당 빌드에서 확인을 마치지 않았습니다. 기기가 없거나 검증이 막혀도 이 상태를 유지합니다.
- 완료: 수정 빌드로 원래 재현 조건과 영향받는 동작을 확인했습니다. 검증 날짜, APK 식별값과 결과 링크를 남깁니다.
- 보류: 지금 처리하지 않기로 한 문제입니다. 이유와 다시 살펴볼 조건을 적고, 사용에 영향을 주는 제한은 완료 보고에도 남깁니다.

수정하지 않아도 되는 관찰은 근거를 남기고 `완료 / 결함 아님`으로, 다른 이슈로 합친 항목은 `완료 / 중복 QA-번호`로 닫습니다. 재현하지 못했다는 이유만으로 결함 아님으로 처리하지 않습니다. 완료했던 문제가 다시 나타나면 기존 번호를 다시 열고 재발한 빌드와 조건을 추가합니다.

수정 후에는 먼저 원래 재현 순서를 실행하고, 수정이 영향을 주는 주변 동작을 확인합니다. 예를 들어 회전 문제라면 재생 중 회전과 일시정지 후 회전, 이어보기까지 확인합니다. 반복이나 간헐적 문제는 같은 조건에서 여러 번 확인하고 횟수를 기록합니다. 자동 검사는 원인에 맞춰 선택하며, 코드와 똑같은 계산을 반복하는 테스트를 추가하지 않습니다.

작업은 해당 완료 기준을 모두 통과했을 때 완료합니다. 열린 긴급 또는 높은 이슈가 그 기준에 영향을 주면 작업도 완료로 처리하지 않습니다. 관련 없는 기존 이슈 때문에 모든 작업을 막지는 않으며, 남은 문제와 미검증 범위를 함께 보고합니다.

## 기록 형식

간단한 문제는 아래 항목을 짧게 채웁니다. 장문의 로그나 같은 재현 설명을 반복하지 않고 검증 기록을 연결합니다.

```text
번호 / 제목:
상태 / 우선순위 / 발견일:
영향과 기대 동작:
재현 조건과 실제 결과:
환경과 빌드: 검증 기록 링크로 대신할 수 있음
증거:
원인: 확인된 사실과 추정 구분
다음 조치 또는 보류 이유와 재확인 조건:
수정과 재검증: 변경 내용, 검사한 빌드, 결과 링크
```

- 수정과 재검증: 2026-11-14, APK SHA-256 `4b508ecd63729d0e48e867f06ba06d568620fd1e321b32afe1f77bb818fc096a`. 일시정지 후 세로 → 가로 → 세로 회전을 두 파일에서 각각 두 번 확인했고 장면, 길이와 정지 상태가 유지됐습니다. 재생 중 회전과 저장 기록 유지도 확인했습니다. [수정 검증](verification.md#2026-11-14-회전과-상태-아이콘-수정-검증)에 주변 동작의 실패도 구분했습니다.

- 기대 동작: 재생 준비 중 일시정지하더라도 준비 완료 후에는 영상 길이와 가능한 조작을 표시해야 합니다.
- 환경과 증거: [2026-11-14 ADB QA](verification.md#2026-11-14-가상-기기-adb-qa)의 초기 일시정지 관찰과 `13-resume-after-stop`, `14-resume-settled`.
- 다음 조치: 준비 전후 일시정지 시점을 나눠 재현하고 QA-001과 같은 원인인지 확인합니다. 같으면 증거를 연결하고 중복으로 정리합니다.
- 수정과 재검증: 미수행.

### QA-005 재생바를 옮겨도 장면이 갱신되지 않음

- 상태: 완료. Android 14 가상 기기와 아래 샘플에서 확인한 범위입니다.
- 우선순위: 높음
- 발견일: 2026-11-14
- 영향과 기대 동작: 재생바의 시간과 실제 영상 장면이 일치해야 합니다. 사용자는 막대를 잡고 옮기는 중과 놓은 뒤 모두 문제를 보고했습니다.
- 최초 재현: 2026-11-14 회전 수정 APK에서 4K 샘플을 재생하고 일시정지한 뒤 회전하고 돌아왔습니다. 막대를 눌러 표시 시간을 `0:01`에서 `0:05`로 바꿨지만 장면은 같았습니다. 이어서 막대를 끄는 중과 놓은 뒤에도 장면이 같았습니다. 이후 저장 위치에서 다시 열었을 때 회전하기 전부터 영상이 회색으로 깨진 모습도 관찰했습니다.
- 비교: 시간이 표시된 640 × 360 샘플은 수정 전과 후 모두 일시정지 상태에서 막대를 놓으면 해당 장면으로 바뀌었습니다. 모든 파일에서 같은 실패가 난다고 판단하지 않습니다.
- 수정 전 코드: 끄는 중에는 표시값만 바꾸고, 손을 놓을 때만 재생기에 위치 이동을 요청합니다. 최초 조사에서는 놓은 뒤 장면이 멈추거나 깨지는 원인을 확정하지 않았습니다.
- 환경과 증거: [수정 검증](verification.md#2026-11-14-회전과-상태-아이콘-수정-검증)의 `42`부터 `45`, `50`부터 `52` 캡처와 `seek-frame-hashes.json`.
- 수정: 끄는 중에도 최신 위치로 이동하고, 손을 놓으면 마지막 위치를 바로 반영합니다. 같은 4K 파일에서 하드웨어 가속을 꺼도 실패했으나 내장 avformat 처리를 우선하면 장면이 정상으로 표시돼 해당 설정을 적용했습니다. 하드웨어 가속은 원래 설정을 유지합니다.
- 수정과 재검증: 2026-11-15, [재생바와 이어보기 수정 검증](verification.md#2026-11-15-재생바와-이어보기-수정-검증)의 최종 APK. 4K MP4에서 1초와 5초 이동을 회전 전후 반복했고, 시간 표시 샘플에서 끄는 중과 놓은 뒤의 장면을 확인했습니다.
- 남은 범위: 실제 기기의 성능과 다른 코덱, 음성과 자막은 미검증입니다.

### QA-006 재생이 끝난 뒤 위치 이동과 재개가 정상적이지 않음

- 상태: 완료. Android 14 가상 기기와 아래 샘플에서 확인한 범위입니다.
- 우선순위: 높음
- 발견일: 2026-11-14
- 영향과 기대 동작: 영상이 끝난 뒤에도 원하는 위치를 고르고 그 장면부터 재생할 수 있어야 합니다.
- 재현: 수정 전 APK에서 4K 샘플을 끝까지 재생한 뒤 막대를 눌러 `0:01`과 `0:05`로 옮겼습니다. 표시 시간만 바뀌고 장면은 같았으며, 재생을 시도한 뒤 재생 실패 안내가 나타났습니다.

### QA-019 SRT 블록 하나의 흠으로 파일 전체가 거절됨

- 2026-11-20 발견, 높음. 코드 리뷰(코드 품질 사례 `2026-11-20-for-me-video-subtitle-review-srt-block-tolerance`)에서 정적 검토로 찾았습니다. 대사가 빈 블록, 시작과 끝 시각이 같은 블록, 블록 사이의 공백만 있는 줄이 두 줄 이상인 구간 중 하나만 있어도 `SrtSubtitles.read`가 파일 전체를 "UTF-8 SRT 파일을 선택해 주세요"로 거절했습니다. 실제 사용자 파일로 재현하지는 않았습니다.
- 원인: 블록마다 `require`로 검사해 한 블록의 실패가 전체 읽기를 멈췄고, 블록 구분 정규식이 공백 줄 여러 개를 한 구분으로 묶지 못했습니다.

### QA-020 SRT의 font와 위치 태그가 글자 그대로 표시됨

### QA-021 교체한 외부 SRT의 영구 읽기 권한을 해제하지 않음

- 2026-11-20 발견, 높음. 코드 리뷰(코드 품질 사례 `2026-11-20-for-me-video-subtitle-review-srt-permission-release`)에서 정적 검토로 찾았습니다. 같은 영상에서 다른 SRT를 고르거나 이번에만 읽을 수 있는 SRT로 바꿔도 이전 SRT의 영구 권한이 남았습니다. Android는 앱의 영구 권한 수에 상한을 두고 넘으면 오래된 권한부터 지우므로, 쌓인 자막 권한 때문에 영상과 폴더 권한이 사라질 수 있습니다. 상한에 닿기 전에는 영향이 없고, 상한 도달은 재현하지 않았습니다.
- 재검증 대기. 저장한 자막 주소가 바뀌면 이전 주소를 다른 영상이 쓰지 않을 때만 권한을 해제합니다. 해제와 공유 유지 조건을 각각 빼면 단위 테스트가 실패했습니다. 저장 형식은 바꾸지 않았습니다.
- 남은 제한: 저장한 SRT를 복원할 때 파일을 찾지 못해도 권한은 해제하지 않습니다. SD 카드 분리나 클라우드 연결 끊김과 실제 삭제를 구별할 수 없어, 해제하면 일시적인 경우에도 권한을 영구히 잃기 때문입니다. 그 영상에서 새 SRT를 고르면 이전 권한이 해제됩니다.

- 완료. 0.3.1에서는 이미 연 영상과 대체 제목을 재생기에 넘깁니다. Android 14 가상 기기에서 같은 영상을 재생하고 24초 위치를 저장했습니다. 파일 열기 자체가 실패하면 다시 선택할 수 있고 정상 파일의 원래 제목도 표시됐습니다. [수정 전후 빌드와 검증 결과](verification.md#2026-11-21-영상-이름-조회-실패와-재생)

### QA-032 화면을 끌어 이동한 뒤 손을 떼면 전체 조작이 뜸

- 2026-11-21 실제 휴대폰 사용 후기에서 발견, 보통. 사용자 원문은 "드래그로 넘김시 드래그끝난 후 화면터치 화면이 노출되는게 불편함"입니다. 조작이 숨겨진 채 영상을 좌우로 끌어 이동하고 손을 떼면, 화면을 눌렀을 때와 같은 전체 조작(뒤로가기, 제목, 10초 이동, 재생 버튼, 화면 모드, 속도)과 진한 덮개가 약 2초 보였습니다. 끌기 종료 처리가 조작을 다시 띄웠고, 끄는 동안 재생기가 잠시 멈춤 상태가 되는 것도 "멈추면 조작 표시" 규칙과 겹쳐 조작을 띄웠습니다. 0.3.1 가상 기기에서 같은 결과를 재현했습니다.
- 0.3.2에서는 손을 떼면 끌기 전 조작 상태로 돌아갑니다. 가상 기기에서 숨긴 상태로 끈 경우 영상만 남고 재생이 이어졌고, 조작이 떠 있던 경우와 일시정지 중 숨긴 경우의 주변 동작도 확인했습니다. 실제 휴대폰 확인 전까지 재검증 대기로 두었습니다. [수정 전후 검증](verification.md#2026-11-21-끌어서-이동한-뒤-조작-표시)
- 완료. 2026-11-21 사용자가 QA에서 해결을 확인했습니다("qa상 해결되었습니다"). 확인한 기기와 설치 빌드는 전달받지 않았습니다.

### QA-033 자동 자막 검색에서 폴더 조회가 실패하면 앱이 종료됨

- 2026-11-23 발견. 0.5.0 가상 기기에서 영상 파일은 읽도록 두고, 파일 제공자가 재생 시작 뒤 폴더 목록 조회에만 `IllegalStateException`을 반환하도록 했다. 영상을 누르자 앱이 종료됐다. 자막이 없는 폴더는 정상 입력이다.
- 완료. 0.6.0에서 같은 조건으로 영상 장면이 계속 바뀌었다. 목록으로 돌아가면 폴더 재선택 안내가 보였고 제공자를 복구한 뒤 새로고침하면 파일이 다시 보였다. [검증 기록](verification.md#2026-11-23-폴더-조회-자막과-다시-보기)

### QA-034 첫 편에 다른 편의 외부 자막이 붙음

- 2026-11-23 발견. 기존 코드에 `Movie.mkv`, `Movie.Part2.mkv`, `Movie.Part2.srt`를 주면 첫 편에 두 번째 편의 자막을 골랐다. 언어 표시가 붙은 다른 편의 자막도 잘못 고를 수 있었다.
- 완료. 0.6.0 단위 검사에서 다른 편 자막 두 가지를 제외했다. 가상 기기의 MP4 두 편 중 두 번째 편에만 외부 SRT의 대사가 보였다. [검증 기록](verification.md#2026-11-23-폴더-조회-자막과-다시-보기)

### QA-035 다국어 SMI의 한국어 선언을 무시함

- 2026-11-23 발견. 언어 이름을 L1과 L2로 정하고 각각 영어와 한국어를 선언한 SMI에서 0.5.0은 첫 번째 영어를 골랐다. 파싱 뒤에는 다른 언어 대사가 남지 않았다. 사용자는 자막 메뉴에서 다른 언어를 선택하는 동작도 요청했다.
- 완료. 0.6.0에서 한국어 대사가 먼저 보였고 영어로 바꾼 후 같은 영상과 자막을 다시 열자 영어가 나왔다. [검증 기록](verification.md#2026-11-23-폴더-조회-자막과-다시-보기)

### QA-036 순서대로 읽는 파일은 다시 보기를 누르면 파일 오류가 남

- 2026-11-23 발견. 0.5.0은 시험용 제공자가 파이프로 보낸 TS를 끝까지 재생했지만 다시 보기를 누르자 파일 오류 화면을 띄웠다. 제공자에 새 연결을 요청하지 않았다.
- 완료. 0.6.0에서 두 번 연속 다시 보기를 눌렀다. 누를 때마다 제공자가 연결을 한 번씩 새로 열었고 화면에서 움직이는 영상과 다음 재생 종료를 확인했다. [검증 기록](verification.md#2026-11-23-폴더-조회-자막과-다시-보기)

### QA-037 대사의 형식 표시 때문에 정상 SRT를 거절함

- 2026-11-23 발견. 0.5.0은 정상 SRT 대사에 `[Events]`나 `<SAMI>`가 있으면 파일 전체의 형식을 다르게 판정했다.

### QA-038 끝난 영상을 다시 보기하면 내장 자막 트랙이 메뉴에서 사라짐

- 확인 필요, 보통, 2026-11-27 발견. 글꼴 실험 중 AI가 가상 기기에서 관찰했다.
- 영향과 기대 동작: 내장 자막을 켜고 끝까지 본 뒤 다시 보기를 누르면 같은 트랙이 계속 표시되고 메뉴에서도 고를 수 있어야 한다.
- 재현 조건과 실제 결과: 0.6.1에서 `font-scope.mkv`를 열고 자막 메뉴에서 내장 트랙을 고른 뒤 끝까지 재생하고 가운데 다시 보기를 눌렀다. 자막이 나오지 않았고 자막 메뉴에는 `자막 끄기`와 `외부 자막 열기`만 남았다. 새 파일로 열고 10초 뒤로 이동한 경우에는 트랙이 유지됐다.
- 환경과 빌드: [2026-11-27 글꼴 실험](verification.md#2026-11-27-첫-재생-글꼴-캐시-시간의-원인-실험), Windows 가상 기기 Android 17.
- 원인: 미확인. 시험 파일은 Python으로 만든 MKV이며 Cues(탐색 색인)가 없다. 2026-11-20 FFmpeg로 만든 MKV에서는 다시 보기 뒤에도 영어 트랙이 유지됐으므로 이 파일에만 생기는 문제일 수 있다.
- 다음 조치: 일반 도구로 만든 MKV와 실제 영상에서 같은 순서로 재현되는지 확인한 뒤 결함 여부를 정한다.
