# 동영상 앱 검증 기록

폴더 탐색 결과는 [2026-11-20 폴더별 영상 목록](#2026-11-20-폴더별-영상-목록)에 있습니다. 자막 검사는 [2026-11-20 자막 선택과 표시](#2026-11-20-자막-선택과-표시)에 있습니다. 2026-11-17 당시 기록은 [대상 SDK 알림의 Lint 등급 변경](#2026-11-17-대상-sdk-알림의-lint-등급-변경)입니다. 이 Mac에서 Lint, 테스트 13개, 디버그와 릴리스 빌드가 통과했지만, 원래 `OldTargetApi` 실패는 이 Mac에서 재현되지 않아 QA-010은 재검증 대기입니다. 그 전 [화면 잠금 검증](#2026-11-17-화면-잠금-검증)에서는 디버그와 릴리스 빌드, 테스트 13개가 통과했으며 Android Lint는 기존 `OldTargetApi` 오류 한 건으로 실패했습니다. Android 17 가상 기기에서 리디자인한 화면, 터치 재생과 화면 잠금을 확인했습니다. 실제 휴대폰 검증과 자막 기능 구현은 수행하지 않았습니다.

이전 빌드의 실패와 수정, 재검증은 날짜별 기록에 보존합니다. 아래 결과는 각 기록에 명시된 APK와 샘플에 한정합니다.

## 현재 확인한 범위

검사 방법은 [QA 절차](../../../docs/qa.md), 발견한 문제의 현재 상태와 다음 조치는 [QA 이슈](qa-issues.md)에서 관리합니다. 아래 날짜별 기록은 당시 결과를 보존합니다.

2026-11-14 기록의 `:app:` 명령은 저장소 루트에서 실행했고, `app/build/` 경로는 모듈을 옮기기 전의 것입니다. 지금은 `apps/video` 폴더에서 `:android:` 모듈로 실행합니다. 아래 기록이 가리키는 당시 증거는 2026-11-15에 검사한 macOS 사본의 `apps/video/android/build/reports/`로 옮겼고, 나머지 루트 `app/build/` 생성물은 정리했습니다. 이 위치도 Git에서 제외되며 `clean` 실행 시 지워집니다. 현재 명령은 [앱 README](../README.md#자동-검사)에 있습니다.

- libVLC `3.7.7` 배포 파일의 16KB 정렬 조건을 확인했습니다. 대상과 결과는 [기술 조사](research.md#배포-파일에서-확인한-호환성)에 있습니다.
- 완성 APK의 16KB 정렬과 포함된 네이티브 라이브러리의 정렬을 확인했습니다.
- 가상 기기에서 설치와 실행, MP4 H.264 샘플 1개의 재생을 확인했습니다. 아래 ADB QA 기록에 통과 항목과 실패 항목을 구분했습니다.
- 기기는 갤럭시 S25와 두 번째 기기를 사용합니다. 두 번째 기기의 모델명과 각 기기의 Android 버전은 확인이 필요합니다.

## 확인용 파일

실제 사용하는 파일부터 목록을 만듭니다. MP4, MKV 같은 파일 형식뿐 아니라 내부 영상과 음성의 압축 방식도 기록합니다. 자막은 영상에 포함된 것과 외부 파일을 나누고 SRT, ASS, SMI와 한글 표시를 확인합니다.

파일마다 다음 정보를 남깁니다.

- 파일을 구분할 이름 또는 식별값
- 파일 형식, 영상과 음성 압축 방식
- 자막 형식, 내장 또는 외부 여부, 문자 인코딩
- 재생 시간과 해상도

모르는 값은 미확인으로 둡니다. 파일 목록에 있다는 이유로 지원한다고 표시하지 않습니다.

## 검사 항목

아래는 목표 기능을 포함한 검사 목록입니다. 폴더 탐색과 자막 선택은 아래 날짜별 샘플을 기준으로 검사했습니다. APK 정렬 검사는 파일 구조 검사이며, 실제 휴대폰에서 실행한 결과는 없습니다.

- 폴더 선택: 허용한 폴더에서 영상을 고르고 재생합니다.
- 파일 선택: 시스템 선택기로 영상 하나를 엽니다. `Download` 안의 파일도 확인합니다.
- 재생: 화면과 소리, 일시정지와 재개, 재생 위치 이동을 확인합니다.
- 홈과 보관함: 썸네일, 제목 검색, 빈 목록과 검색 결과 없음, 긴 제목과 최근 20개 기록을 확인합니다.
- 터치 재생: 영상 영역을 눌러 재생과 일시정지를 전환하고, 재생바와 버튼이 중복 동작하지 않는지 확인합니다.
- 화면 잠금: 재생과 일시정지 상태에서 터치, 위치 이동과 뒤로 가기를 차단하고, 회전 후에도 잠금 유지와 해제가 가능한지 확인합니다.
- 자막: 내장 자막과 외부 자막의 한글 표시, 선택과 끄기, 싱크와 글자 크기 조절을 형식별로 확인합니다.
- 화면 전환: 화면 회전과 다른 화면에서 복귀한 뒤 재생 상태를 확인합니다. 재생 종료 후 사용한 자원을 해제하는지도 확인합니다.
- 이어보기: 영상 중간에 앱을 종료하고 다시 열어 저장한 위치에서 재생합니다. 종료 방법과 기대 위치, 실제 위치를 기록합니다.
- 기기 재시작: 재시작 후 파일 접근과 이어보기를 확인합니다.
- 업데이트: 이전 버전에서 재생 위치를 저장한 뒤 앱을 덮어 설치합니다. 데이터 초기화 없이 파일 접근과 이어보기를 확인합니다.
- 접근 실패: 권한 거절과 취소, 파일 이동과 삭제 시 이유를 알리고 다시 선택할 수 있는지 확인합니다.
- 16KB 환경: 완성 APK의 정렬과 해당 환경에서의 설치, 실행을 확인합니다. 일반 기기에서의 성공과 구분합니다.
- 기기별 사용: 같은 파일과 재생 시간에서 끊김, 발열, 배터리 사용을 확인합니다. 관찰한 현상과 측정값을 구분합니다.

### 통과한 항목

- 파일 선택과 취소: 영상 열기에서 시스템 Downloads 선택기가 열렸습니다. 뒤로 가기로 취소해도 기존 최근 영상과 `0:01` 기록이 유지됐습니다. 다시 열어 샘플을 선택하면 재생 화면으로 이동했습니다.
- 영상 재생: 재생 시간이 `0:03`에서 `0:10`으로 진행됐고 서로 다른 시점의 화면에서 영상 장면의 변화를 확인했습니다. 연속 프레임 성능이나 끊김 여부를 측정한 결과는 아닙니다.
- 일시정지: `0:20 / 0:23`과 재생 버튼이 표시됐고, 3초 대기 후 다시 수집한 화면 요소에서도 시간이 유지됐습니다.
- 위치 이동과 재개: 일시정지 상태에서 막대를 눌러 `0:20`에서 `0:06`으로 이동했습니다. 재생 후 다시 멈췄을 때 `0:09`로 진행됐습니다.
- 종료 후 이어보기: 영상을 닫으면 최근 영상에 `0:09`가 표시됐습니다. `am force-stop`으로 앱을 강제 종료하고 다시 실행해도 기록이 남았으며, 최근 영상을 열어 재생한 뒤 `0:12 / 0:23`으로 진행됐습니다.
- 같은 APK 덮어 설치: 설치 전후 최근 영상의 `0:12` 기록이 유지됐습니다. 파일 선택기를 다시 거치지 않고 최근 영상을 열어 `0:13 / 0:23`으로 재생됐고 이후 `0:15`에서 일시정지했습니다. 다른 버전으로의 업데이트나 저장 구조 변경 검증은 아닙니다.
- 원본 보존: QA 후 가상 기기에 있는 샘플의 SHA-256이 앞서 복사한 샘플과 일치했습니다. 화면 회전 설정은 검사 전의 `free`로 복원했습니다.

### 발견한 문제

**일시정지 후 화면 회전 시 영상과 길이 표시가 사라짐 — 실패**

1. 샘플을 재생하고 `0:12 / 0:23`에서 일시정지합니다.
2. 세로에서 가로로 회전합니다.
3. 영상 영역이 검게 바뀌고 `0:12 / 0:00`으로 표시되며 위치 이동 막대를 사용할 수 없습니다.

같은 APK를 덮어 설치한 뒤 `0:15 / 0:23`에서 다시 시도해도 `0:15 / 0:00`과 검은 화면으로 재현됐습니다. 재생 버튼을 누른 뒤 6초 후 수집한 화면에서는 `0:17 / 0:23`과 영상이 돌아왔습니다. 기대 동작은 일시정지한 장면, 전체 길이와 위치 이동 가능 상태를 회전 후에도 유지하는 것입니다.

재생바는 끄는 중에도 최신 위치를 요청하고 손을 놓으면 마지막 요청을 바로 반영합니다. 재생 중 시작한 드래그는 잠시 멈춘 뒤 끝나면 재생을 이어가며, 일시정지 상태에서 시작했다면 그대로 멈춰 있습니다. 사용자가 선택한 위치는 시간 이벤트가 없어도 저장합니다.

종료 후 재개에서는 선택한 위치를 0으로 바꾸지 않도록 했습니다. 입력을 다시 만드는 것만으로는 빈 버퍼 오류가 남았으며, 파일 읽기 위치를 처음으로 되돌린 뒤 다시 준비하자 재생됐습니다. 연결을 다시 준비할 때 영상 출력도 재연결합니다. 선택한 시간과 일시정지 의도는 유지합니다. 구현 근거와 설정은 [기술 조사](research.md#재생-위치-이동-처리)에 남겼습니다.

### 가상 기기 결과

- QA-005 통과: 최종 APK에서 4K MP4의 1초 → 5초 이동으로 서로 다른 정상 장면이 표시됐습니다. 5초에서 세로 → 가로 → 세로로 회전해도 장면과 길이, 일시정지가 유지됐고, 같은 위치 이동을 다시 확인했습니다.
- 드래그 중 장면 확인: 시간 표시 MP4에서 손을 놓기 전 `07.60` 장면과 화면의 `0:07`을 확인했습니다. 놓은 뒤에는 `14.20`과 `0:14`, 다시 5초를 고른 뒤에는 `05.40`과 `0:05`가 표시됐습니다. 화면 요소 XML과 PNG는 순서대로 수집하므로 움직이는 중에는 서로 약 1초 차이가 날 수 있습니다.
- QA-007 통과: 두 MP4 샘플에서 일시정지 중 5초로 옮긴 뒤 닫으면 최근 기록이 `0:05`였습니다. 강제 종료와 재실행 뒤에도 유지됐습니다. 시간 표시 샘플을 다시 열어 재생했을 때 저장 위치 이후의 `09.30` 장면을 확인했습니다.
- QA-006 통과: 두 MP4 샘플에서 끝까지 재생한 뒤 5초를 고르면 해당 장면이 표시되고, 재생하면 약 9초로 진행됐습니다. 각 파일을 다시 끝낸 뒤 처음부터 재생하는 경우도 확인했습니다. 재생 실패 안내는 나타나지 않았습니다.
- 기존 수정 확인: 재생바 이동 후 회전해도 장면, 길이와 정지 상태가 유지됐습니다. 세로와 가로 화면의 상태 아이콘도 밝게 표시됐습니다.
- MKV와 재생 중 드래그: 5초를 선택했을 때 `05.40` 장면이 표시됐습니다. 재생 중 막대를 잡으면 잠시 멈춰 이동 중인 `10.10` 장면을 표시했고, 놓은 뒤 재생이 이어져 `16.50`에서 `20.90`으로 진행됐습니다. 다시 5초로 옮기고 닫았을 때 최근 기록도 `0:05`였습니다.
- 보존 확인: 설치된 APK는 위 최종 SHA-256과 일치했습니다. 검사 후 기존 4K 샘플의 SHA-256도 검사 전과 같았습니다. 회전 설정은 검사 전의 `free`로 되돌렸습니다.

APK는 Android 앱 설치 파일입니다. SHA-256은 검사한 파일을 구분하는 값이며, 같은 버전명으로 다시 빌드한 파일도 구별하는 데 사용합니다.

## 2026-11-22 첫 재생 대기 표시와 글꼴 캐시 예열 교체

QA-028의 후속 수정이며 버전은 0.4.1입니다. 이전 수정 뒤에도 앱을 켜자마자 재생하면 글꼴 캐시가 다 만들어질 때까지 기다려야 했습니다. 이 수정은 그 대기 시간을 없애지 않고 다음 두 가지를 바꿉니다.

- **첫 장면까지 준비 표시.** 이전에는 재생기 객체를 만들자마자 ‘영상을 여는 중’이 사라졌습니다. libVLC는 재생 시작 알림을 영상 출력보다 먼저 보내므로, 글꼴 캐시를 만드는 동안 검은 화면에 일시정지 버튼과 시간만 보였습니다. 이제 영상 출력이 생기거나(영상 트랙이 없는 파일은 시간이 흐르면), 멈춤, 종료, 오류가 될 때까지 표시를 유지합니다. 표시는 가운데 재생 버튼과 겹치지 않게 그 아래에 둡니다.
- **예열 방식 교체.** 화면 없이 16×16 PNG를 재생하던 예열을 libvlc-all 3.7.7의 공개 함수 `LibVLC.buildFontCache()`로 바꿨습니다. 작업 스레드에서 실행하고, 끝까지 마치면 다음 실행부터는 하지 않습니다. 예열 중에 영상을 열면 재생기는 예열이 끝날 때까지 기다렸다가 만들어지고, 그동안 ‘처음 한 번만 글꼴을 준비하는 중’을 표시합니다.

## 2026-11-22 보관함 폴더와 최근 본 영상 탭

사용자 피드백 "폴더와 최근 본 영상 탭을 나눠야한다"에 따라 보관함을 두 탭으로 나눴습니다. 보관함 화면이 바뀌었으므로 [버전 규칙](../README.md#버전)에 따라 0.5.0(`versionCode` 500)으로 올렸습니다. 탭의 위치, 이름과 검색 위치는 사용자가 정하지 않아 AI가 아래 기본값으로 정했고, 결과 보고 뒤 사용자가 그대로 두기로 했습니다("이대로 두기").

- **탭 위치와 이름.** 아래 탭(홈, 보관함, 영상 열기)은 그대로 두고, 보관함 머리 줄 아래에 글자 탭 `폴더`와 `최근 본 영상`을 둡니다. 고른 탭은 흰 글자와 2dp 밑줄, 나머지는 흐린 글자입니다. 최근 본 영상 탭 옆에는 기록 수(`1편`)를 흐리게 붙입니다. 글자는 기존 소제목과 같은 16sp 650이고, 탭 높이는 48dp입니다. 문자열 `recently_opened`(최근에 연 영상)는 `recently_watched`(최근 본 영상)로 바꿨습니다.
- **검색.** 제목 검색은 최근 기록만 거르므로 최근 본 영상 탭 맨 위에만 둡니다. 묶음 소제목 `폴더`와 `최근에 연 영상`은 탭 이름이 대신해 없앴습니다.
- **폴더 탭.** 폴더 행 뒤에 폴더 추가 행(`ic_folder_add`)을 둡니다. 이전에는 폴더가 있으면 소제목 오른쪽 밑줄 글자, 없으면 추가 행이었는데, 소제목이 없어져 두 경우 모두 목록 끝의 추가 행으로 맞췄습니다.
- **탭 고르기.** 앱을 새로 켜면 폴더 탭이 먼저 보입니다. 홈에 다녀오면 보던 탭으로 돌아옵니다. 홈의 `폴더별 영상` 제목은 폴더 탭을, `계속 시청하기`와 `최근 영상` 제목은 최근 본 영상 탭을 엽니다. 탭마다 스크롤 위치를 따로 둡니다. 버전 표시는 두 탭 끝에 모두 있습니다.
- **확인.** 이 Windows 머신의 Medium_Phone_API_37.0 가상 기기(Android 17, API 37, x86_64, 1080×2400, 420dpi)에서 0.1.0이 설치된 상태에 덮어 설치했습니다. 앱 데이터는 지우지 않았고, 기존 기록 `qa-clock-a.mp4`가 홈과 최근 본 영상 탭에 그대로 보였습니다. 화면 요소 XML로 다음을 확인했습니다.
  - 앱을 강제 종료하고 다시 켠 뒤 보관함을 누르면 폴더 탭이 선택되고 `폴더 추가` 행과 `버전 0.5.0`이 보였습니다(`11-cold-library`). 탭 높이는 126px(48dp)입니다.
  - 최근 본 영상 탭을 고르고 홈에 갔다가 아래 탭 보관함으로 돌아오면 최근 본 영상 탭이 그대로 선택돼 있었습니다(`05`~`07`). 홈의 `최근 영상` 제목을 누르면 최근 본 영상 탭이 열렸습니다(`09`).
  - 검색어 `zzz`는 `찾는 영상이 없어요`, `clock`은 `qa-clock-a.mp4` 한 편을 보였습니다. 폴더 탭에 갔다 돌아와도 검색어와 결과가 남았습니다(`13`, `14`, `17`).
  - 최근 본 영상 탭에서 영상을 재생하고 뒤로 가기로 닫거나, 상세를 열고 닫으면 같은 탭과 검색어로 돌아왔습니다(`19c`, `21`). 처음 재생할 때 Android의 전체 화면 안내(`Viewing full screen`)가 한 번 떠 닫았습니다.
  - 로그에 앱 종료 오류(`FATAL EXCEPTION`)는 없었습니다. 증거는 이 머신의 `android/build/reports/qa/20261122-library-tabs/`에 있습니다.
- **자동 검사.** `./gradlew --no-daemon :android:lintDebug :android:testDebugUnitTest :android:assembleDebug :android:assembleRelease`가 통과했습니다. 단위 테스트 52개(실패 0), Android Lint는 오류와 경고 0개, 정보 13개입니다. 탭 동작은 단위 테스트가 다루지 않아 테스트를 추가하지 않았습니다. 두 APK의 버전 정보가 0.5.0과 500인 것을 `aapt`로 확인했습니다. 디버그 APK SHA-256은 `fe62643963bf77be742319148b2e881a80015fbb9ad2f6aa967183ae95ab0d5a`(가상 기기에 설치한 파일과 같음), 서명하지 않은 릴리스 APK는 `dbfb97c7959579a7d1f708d536b76cda6e2209c566d84f5d71a3f2ae3efbb3ad`입니다.
- **미검증.** 실제 휴대폰, 폴더를 등록한 상태의 폴더 탭(폴더 행 뒤 추가 행), 선택기에서 폴더를 새로 추가한 뒤 바로 열리는지, 가로 화면, 큰 글자에서 탭 이름 넘침, TalkBack으로 탭 이름과 선택 상태 읽기, 화면 재생성(회전과 야간 모드) 뒤 탭 유지는 확인하지 않았습니다. 취향 확인 절차에 따라 스크린숏을 찍지 않아 탭 모양과 간격의 체감도 보지 않았습니다.

## 2026-11-23 폴더 조회, 자막과 다시 보기

- macOS arm64의 Android API 37 가상 기기 `Medium_Phone_API_37.0`을 읽기 전용으로 실행했다. 기존 앱 데이터를 둔 채 0.5.0에서 0.6.0 디버그 빌드로 덮어 설치했다. 가상 기기에만 둔 시험용 문서 제공자가 시스템 선택기로 폴더 권한을 제공했다. 샘플은 모두 H.264 180×240, 12fps이며 음성 트랙은 없다. MP4는 12초, 순차 전송용 MPEG-TS는 5초다.
- **수정 전.** 0.5.0에서 새 회귀 검사 네 개가 실패했다. 폴더 조회 예외가 그대로 전달됐고 첫 편에 두 번째 편 자막이 선택됐다. 언어 선언이 있는 SMI는 영어를 골랐고, 대사에 형식 표시가 있는 SRT는 거절됐다. 가상 기기에서는 폴더를 연 뒤 자막 검색 때만 제공자가 예외를 반환하자 앱이 종료됐다. TS는 끝까지 볼 수 있었으나 다시 보기에서 연결을 새로 열지 않고 파일 오류가 표시됐다.
- **폴더와 자막.** 0.6.0에서는 같은 예외에서도 영상의 색상 패턴이 움직였다. 폴더로 돌아오면 재선택 안내가 표시되고 조회를 복구한 뒤 새로고침하면 목록이 돌아왔다. 시험용 폴더의 접근 권한은 업데이트 뒤에도 유지됐다. 정상 폴더에서 첫 편은 외부 SRT 없이 재생됐고 두 번째 편에만 해당 대사가 보였다. SRT 대사의 `[Events]`와 `<SAMI> test`가 그대로 두 줄로 표시됐다.
- **언어 선택과 복원.** SMI에는 L1(영어)과 L2(한국어)의 언어 선언과 별도 대사를 넣었다. 최초 재생은 한국어였다. 메뉴에서 영어를 고른 뒤 다시 열고 앱을 덮어 설치한 뒤에도 영어 대사가 보였다. 일시정지 중 한국어로 바꾸자 즉시 한국어가 보였으며, 다시 열면 약 3초의 이어보기 위치와 한국어가 함께 복원됐다.
- **다시 보기.** 순차 전송 TS를 끝까지 본 뒤 다시 보기를 두 번 연속 실행했다. 제공자의 열기 횟수는 26, 27, 28로 한 번씩 늘었고, 각 회차에 색상 패턴이 있는 영상 캡처 7장 사이에서 장면 변화와 재생 종료를 확인했다. 일반 MP4도 다시 보기 후 영상이 움직였다. 초기 측정에서는 두 캡처 사이 평균 차이가 한 번 0.43에 그쳐 영상 출력 판단을 보류했다. 최종 검사는 영상 영역의 색상 패턴을 먼저 확인하고 여러 시점의 변화를 사용했다.
- **다시 열기 실패.** 최초 재생은 허용한 뒤 새 읽기 요청에서 권한 거절 또는 파일 이동에 해당하는 예외를 반환하면 파일 재선택 안내가 나왔다. 시스템 선택기를 취소하면 안내로 돌아왔고, 제공자의 파일 접근을 복구한 뒤 폴더에서 다시 열어 실제 장면 변화를 확인했다.
- **자동 검사와 빌드.** 단위 테스트 56개 통과, Android Lint 오류와 경고 0건. 디버그와 서명하지 않은 릴리스 APK를 빌드했다. 0.6.0 디버그 APK의 SHA-256은 `56a471e18ec80b8744beb34e21689baf122c055ba2b012568ade233aea6c2f08`, 릴리스 APK는 `e90074c46779f2a5ee73b855d18f1c7f09947c3945afd8988a24baf2c75e040b`이다.
- **확인 범위.** 실제 휴대폰과 상용 클라우드 제공자, 음성 재생은 이번 검증에 포함하지 않았다. QA-033~037의 최초 실패와 최종 상태는 [QA 이슈](qa-issues.md#qa-033-자동-자막-검색에서-폴더-조회가-실패하면-앱이-종료됨)에 있다.
