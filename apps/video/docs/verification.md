# 동영상 앱 검증 기록

2026-11-15에 재생바 장면 갱신, 종료 후 재개와 일시정지 중 위치 저장 문제를 수정했습니다. 자동 검사와 Android 14 가상 기기에서 재검증한 결과는 아래에 기록했습니다. 2026-11-17에는 UI 컴파일 오류를 수정하고 디버그/릴리스 빌드, 테스트 13개와 Android 17 가상 기기의 일부 동작을 확인했습니다. Android Lint는 대상 SDK 관련 1건으로 실패했습니다. 실제 기기 검증은 아직 하지 않았습니다.

## 현재 확인한 범위

검사 방법은 [QA 절차](../../../docs/qa.md), 발견한 문제의 현재 상태와 다음 조치는 [QA 이슈](qa-issues.md)에서 관리합니다. 아래 날짜별 기록은 당시 결과를 보존합니다.

2026-11-14 기록의 `:app:` 명령은 저장소 루트에서 실행했고, `app/build/` 경로는 모듈을 옮기기 전의 것입니다. 지금은 `apps/video` 폴더에서 `:android:` 모듈로 실행합니다. 아래 기록이 가리키는 당시 증거는 2026-11-15에 검사한 macOS 사본의 `apps/video/android/build/reports/`로 옮겼고, 나머지 루트 `app/build/` 생성물은 정리했습니다. 이 위치도 Git에서 제외되며 `clean` 실행 시 지워집니다. 현재 명령은 [앱 README](../README.md#자동-검사)에 있습니다.

- libVLC `3.7.7` 배포 파일의 16KB 정렬 조건을 확인했습니다. 대상과 결과는 [기술 조사](research.md#배포-파일에서-확인한-호환성)에 있습니다.
- 완성 APK의 16KB 정렬과 포함된 네이티브 라이브러리의 정렬을 확인했습니다.
- 가상 기기에서 설치와 실행, MP4 H.264 샘플 1개의 재생을 확인했습니다. 아래 ADB QA 기록에 통과 항목과 실패 항목을 구분했습니다.
- 기기는 갤럭시 S25와 두 번째 기기를 사용합니다. 두 번째 기기의 모델명과 각 기기의 Android 버전은 확인이 필요합니다.

## 확인용 파일

실제 사용하는 파일부터 목록을 만듭니다. MP4, MKV 같은 파일 형식뿐 아니라 내부 영상과 음성의 압축 방식도 기록합니다. 자막은 영상에 포함된 것과 외부 파일을 나누고 SRT, ASS, SMI와 한글 표시를 확인합니다.

파일마다 다음 정보를 남깁니다.

- 파일을 구분할 이름 또는 식별값
- 파일 형식, 영상과 음성 압축 방식
- 자막 형식, 내장 또는 외부 여부, 문자 인코딩
- 재생 시간과 해상도

모르는 값은 미확인으로 둡니다. 파일 목록에 있다는 이유로 지원한다고 표시하지 않습니다.

## 검사 항목

아래는 기기에서 수행할 항목입니다. APK 정렬 검사 외에는 실제 기기에서 통과한 결과가 없습니다.

- 폴더 선택: 허용한 폴더에서 영상을 고르고 재생합니다.
- 파일 선택: 시스템 선택기로 영상 하나를 엽니다. `Download` 안의 파일도 확인합니다.
- 재생: 화면과 소리, 일시정지와 재개, 재생 위치 이동을 확인합니다.
- 자막: 내장 자막과 외부 자막의 한글 표시, 표시 시점을 확인합니다.
- 화면 전환: 화면 회전과 다른 화면에서 복귀한 뒤 재생 상태를 확인합니다. 재생 종료 후 사용한 자원을 해제하는지도 확인합니다.
- 이어보기: 영상 중간에 앱을 종료하고 다시 열어 저장한 위치에서 재생합니다. 종료 방법과 기대 위치, 실제 위치를 기록합니다.
- 기기 재시작: 재시작 후 파일 접근과 이어보기를 확인합니다.
- 업데이트: 이전 버전에서 재생 위치를 저장한 뒤 앱을 덮어 설치합니다. 데이터 초기화 없이 파일 접근과 이어보기를 확인합니다.
- 접근 실패: 권한 거절과 취소, 파일 이동과 삭제 시 이유를 알리고 다시 선택할 수 있는지 확인합니다.
- 16KB 환경: 완성 APK의 정렬과 해당 환경에서의 설치, 실행을 확인합니다. 일반 기기에서의 성공과 구분합니다.
- 기기별 사용: 같은 파일과 재생 시간에서 끊김, 발열, 배터리 사용을 확인합니다. 관찰한 현상과 측정값을 구분합니다.

### 통과한 항목

- 파일 선택과 취소: 영상 열기에서 시스템 Downloads 선택기가 열렸습니다. 뒤로 가기로 취소해도 기존 최근 영상과 `0:01` 기록이 유지됐습니다. 다시 열어 샘플을 선택하면 재생 화면으로 이동했습니다.
- 영상 재생: 재생 시간이 `0:03`에서 `0:10`으로 진행됐고 서로 다른 시점의 화면에서 영상 장면의 변화를 확인했습니다. 연속 프레임 성능이나 끊김 여부를 측정한 결과는 아닙니다.
- 일시정지: `0:20 / 0:23`과 재생 버튼이 표시됐고, 3초 대기 후 다시 수집한 화면 요소에서도 시간이 유지됐습니다.
- 위치 이동과 재개: 일시정지 상태에서 막대를 눌러 `0:20`에서 `0:06`으로 이동했습니다. 재생 후 다시 멈췄을 때 `0:09`로 진행됐습니다.
- 종료 후 이어보기: 영상을 닫으면 최근 영상에 `0:09`가 표시됐습니다. `am force-stop`으로 앱을 강제 종료하고 다시 실행해도 기록이 남았으며, 최근 영상을 열어 재생한 뒤 `0:12 / 0:23`으로 진행됐습니다.
- 같은 APK 덮어 설치: 설치 전후 최근 영상의 `0:12` 기록이 유지됐습니다. 파일 선택기를 다시 거치지 않고 최근 영상을 열어 `0:13 / 0:23`으로 재생됐고 이후 `0:15`에서 일시정지했습니다. 다른 버전으로의 업데이트나 저장 구조 변경 검증은 아닙니다.
- 원본 보존: QA 후 가상 기기에 있는 샘플의 SHA-256이 앞서 복사한 샘플과 일치했습니다. 화면 회전 설정은 검사 전의 `free`로 복원했습니다.

### 발견한 문제

**일시정지 후 화면 회전 시 영상과 길이 표시가 사라짐 — 실패**

1. 샘플을 재생하고 `0:12 / 0:23`에서 일시정지합니다.
2. 세로에서 가로로 회전합니다.
3. 영상 영역이 검게 바뀌고 `0:12 / 0:00`으로 표시되며 위치 이동 막대를 사용할 수 없습니다.

같은 APK를 덮어 설치한 뒤 `0:15 / 0:23`에서 다시 시도해도 `0:15 / 0:00`과 검은 화면으로 재현됐습니다. 재생 버튼을 누른 뒤 6초 후 수집한 화면에서는 `0:17 / 0:23`과 영상이 돌아왔습니다. 기대 동작은 일시정지한 장면, 전체 길이와 위치 이동 가능 상태를 회전 후에도 유지하는 것입니다.

코드에서는 화면 재생성 시 `VlcPlayback`을 새로 만들고, 일시정지 의도가 남아 있으면 재생을 시작하지 않습니다. 새 재생기의 장면과 길이를 준비하는 과정이 없는 것이 원인 후보입니다. 일시정지를 유지하면서 장면과 길이를 복원하도록 수정한 뒤 같은 순서로 재검증해야 합니다. 파일을 연 직후 빠르게 일시정지했을 때도 `0:09 / 0:00`이 유지되는 현상을 관찰했지만, 이 조건은 반복 검증하지 않았습니다.

**어두운 배경에서 상태 아이콘이 잘 보이지 않음 — 실패**

앱의 어두운 배경 위에 시계, 배터리와 통신 상태가 검게 표시됩니다. 세로와 가로 화면에서 확인했습니다. `MainActivity`의 기본 `enableEdgeToEdge()` 설정과 앱에 고정한 어두운 색상 구성이 맞는지 확인하고, 시스템 상태 아이콘의 밝기를 앱 배경에 맞춰야 합니다.

추가로 같은 샘플이 최근 목록에 두 줄로 표시됐습니다. 저장소 사본을 조회하니 Downloads 선택기가 반환한 `raw:`와 `msf:`의 서로 다른 파일 주소로 각각 저장돼 있었습니다. 파일 주소별로 기록하는 현재 동작은 확인했지만, 같은 파일로 합칠 기준은 이번 QA에서 결정하지 않았습니다.

### 증거와 남은 검증

화면 PNG, 화면 요소 XML, 앱 로그와 식별값은 Git에서 제외되는 `apps/video/android/build/reports/adb-qa-20261114/`에 남겼습니다. 파일명은 수집 순서와 당시 검사 의도를 나타내며, 통과 판정은 위 결과를 기준으로 합니다. XML과 PNG는 차례로 수집해 재생 중 표시 시간이 약 1초 다를 수 있습니다.

- 선택과 취소: `02-picker`, `03-picker-cancel`

### 재생바 조사 결과

**장면 갱신 — 일부 조건 실패, QA-005**
