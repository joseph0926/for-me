# QA-018 비디오 앱 리디자인 제보 자료

Android 비디오 앱에 웹사이트용 `design-taste-frontend` 2.5.1의 색상과 배치 지침을 적용한 사례입니다. 화면은 Jetpack Compose로 구현했으며, 아래 이미지는 Android 17 가상 기기에서 ADB로 캡처했습니다.

2026-11-20 사용자 의견 원문입니다.

> 색깔, 폰트 배치 모든게 ai-slop으로 보입니다.

## 보관한 파일

- [리디자인 소스 패치](redesign.patch)는 리디자인 직전의 메인 소스를 기준으로 Android 코드, 화면 문구와 문서 등 13개 파일의 변경을 담습니다.
- [리디자인 디버그 APK](redesign.apk)는 해당 화면을 실행할 수 있는 로컬 설치 파일입니다. 앱 버전은 0.1.0(1)이고 SHA-256은 `35ebe86af741183f7c8f6acecd01914041fe19ebfdaa1593041633500c9b32a7`입니다. APK는 Git 추적에서 제외했습니다.

## 메인 앱 롤백 확인

복원한 메인 빌드를 같은 가상 기기에 덮어 설치했습니다. 기존 홈에 영상 두 편과 이어보기 시간이 표시됐고, 등록한 폴더에서 영상을 열어 기존 자막 선택 창과 저장한 표시 시각을 확인했습니다. 같은 폴더의 롤백 전후 비교에서는 화면 상단 100픽셀을 제외한 나머지가 리디자인 직전 캡처와 픽셀 단위로 일치했습니다. [복원한 홈](restored-home.png), [폴더](restored-folder.png), [자막](restored-subtitles.png)

복원한 소스에서 Android Lint, 단위 테스트 20개, 디버그 및 릴리스 빌드가 통과했습니다. 새 디버그 APK의 SHA-256은 `b540602d7ac53712dd42e1b69592bd1124e18a74e8371ba1b05768dc432688b0`입니다. 리디자인 직전 APK와 압축 내부 파일을 비교했을 때 `classes4.dex` 한 파일에 차이가 있었고, 그 안에서 실행 명령이 달라진 곳은 Compose가 MainActivity에 생성한 함수 하나였습니다.

## 2026-11-20 Windows PC 가상 기기 재확인

처음 작성한 README는 글꼴을 모두 Pretendard로 유지했다고 적었습니다. 패치와 화면을 대조한 뒤 이 재확인에서 고정폭 글꼴과 가로 메뉴 색을 확인하고 위 설명을 고쳤습니다.

- 기기와 빌드: Windows PC의 Android 17(API 37) x86_64 가상 기기 `sdk_gphone64_x86_64`에서 ADB로 조작했습니다. 이 기기에는 앱이 설치돼 있지 않았습니다. 위의 리디자인 APK를 새로 설치했습니다.
- 시험 영상: `adb shell screenrecord --bugreport`로 기기에서 만든 38초 MP4입니다. H.264, 640 × 360이고 음성과 자막은 없습니다. 위 캡처에 쓴 MKV 영상은 이 PC에 없어 자막 화면은 다시 확인하지 않았습니다.
- 리디자인 결과: 홈의 이어보기 카드와 최근 목록에서 시간이 "0 : 10 / 0 : 38"처럼 고정폭 글꼴로 표시됐고, 재생바 시간과 폴더 개수도 같았습니다. 가로 보관함에서 선택한 "보관함" 글자의 주된 색은 `#625B71`, 선택하지 않은 "홈"은 `#555A50`이었습니다. [리디자인 홈](recheck-redesign-home.png), [리디자인 가로 보관함](recheck-redesign-library-wide.png)
- 메인 빌드 결과: 이 PC에서 만든 메인 디버그 APK(SHA-256 `e1a016de263d74c0a12322760358571db74c2c02b92f5177e00727d40666487d`)에서는 어두운 바탕, "for me" 제목과 "계속 시청하기" 목록이 나왔고, 시간은 "0:00 / 0:38"처럼 일반 글꼴로 표시됐습니다. 이 APK는 아직 커밋하지 않은 자막 수정(QA-019~025)이 반영된 작업 트리에서 빌드됐을 수 있습니다. [메인 홈](recheck-main-home.png)
- 확인하지 못한 항목: 리디자인 APK는 Mac의 디버그 키로, 이 PC의 메인 APK는 다른 디버그 키로 서명돼 서로 덮어 설치할 수 없습니다. 리디자인 앱을 지운 뒤 메인 빌드를 새로 설치했으므로, 덮어 설치 후 이어보기 기록 보존은 이 PC에서 다시 확인하지 않았습니다.
- 원인을 판단하지 않은 현상: 두 빌드 모두 "10초 앞으로"를 눌러도 재생 화면의 위치가 0:00에 머물렀고, 홈에 저장된 위치는 리디자인 0:10, 메인 0:00이었습니다. 화면 녹화로 만든 영상의 프레임이 매우 적은 탓일 수 있어 앱 결함으로 판정하지 않았습니다.
