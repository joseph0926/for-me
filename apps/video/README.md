# 장면

휴대폰에 저장한 파일을 재생하는 동영상 앱입니다. 앱 이름은 **장면**이며, 저장소 폴더(`apps/video`)와 앱 식별자(`dev.forme.video`)는 기존 이어보기 기록과 파일 접근 권한을 지키기 위해 바꾸지 않습니다. Android부터 개발하고, 이후 Windows와 macOS로 확장합니다.

공통 개발 절차는 [개발 절차](../../docs/development.md), 조작과 증거 수집 방법은 [QA 절차](../../docs/qa.md)를 따릅니다.

## 현재 상태

2026-11-20 기준으로 Android 시제품을 개발 중입니다.

- 시스템 파일 선택기로 영상을 열고, 재생 위치를 저장해 이어봅니다.
- Viewgrain의 SCENE과 FRAME 레퍼런스로 홈, 보관함과 재생 화면을 리디자인했습니다. Viewgrain은 이후 [폐기](../../docs/retired-viewgrain.md)했습니다. 실제 파일의 썸네일과 최근 20개 기록을 표시하며, 보관함에서 제목을 검색합니다.
- 영상 영역을 누르면 조작이 나타나거나 사라지고, 재생과 일시정지는 가운데 재생 버튼으로만 바꿉니다. 화면 왼쪽이나 오른쪽을 두 번 누르면 10초 뒤로 또는 앞으로 이동하고, 표시가 떠 있는 동안 같은 쪽을 한 번 더 누를 때마다 10초씩 더 갑니다. 양옆은 두 번째 누르기를 기다리므로 한 번 누르면 약 0.26초 뒤에 조작이 바뀌고, 가운데는 바로 바뀝니다. 영상 위를 좌우로 끌면 끈 만큼 앞이나 뒤로 이동하며(끝에서 끝까지 90초), 끄는 동안 가운데에 옮겨 갈 시각과 이동량을 보여 줍니다. 손을 떼면 끌기 전 조작 상태로 돌아가, 조작이 숨겨져 있었으면 영상만 남고 떠 있었으면 조작이 다시 보입니다. 조작이 보이는 동안 영상 전체를 어둡게 덮고, 10초 이동과 재생 버튼은 화면 가운데, 재생바는 맨 아래에 둡니다. 재생바를 끄는 동안에는 재생바와 시간 말풍선만 남기고, 끝까지 보면 가운데 버튼이 다시 보기로 바뀝니다. 폴더에서 연 영상이면 그 아래 **다음 영상: 제목** 버튼으로 같은 폴더의 다음 영상을 엽니다. 파일 제공자가 영상을 순서대로만 보내 주면 다시 보기에서 같은 영상을 새로 열어 처음부터 재생합니다.
- 가로로 긴 영상은 재생을 시작하면 화면이 가로로, 세로로 긴 영상은 세로로 돌아갑니다. 위쪽 회전 버튼으로 가로와 세로를 직접 바꿀 수 있고, 목록으로 돌아가면 원래 방향 설정으로 돌아갑니다.
- 재생하는 동안 상태줄과 하단바를 숨기고 영상을 화면 끝까지 그립니다. 화면 가장자리를 쓸어 넘기면 막대가 잠깐 나타나고, 목록으로 돌아가면 다시 보입니다. 조작 버튼은 카메라 구멍 같은 화면 잘림 부분을 피해 배치합니다.
- 재생 화면 왼쪽 가장자리의 화면 모드 버튼을 누를 때마다 **맞춤**(영상 전체), **채우기**(넘치는 부분을 잘라 화면을 채움), **늘이기**(비율을 무시하고 화면에 맞춤) 순서로 바뀝니다. 고른 모드는 모든 영상에 쓰이고 앱을 다시 시작해도 유지됩니다.
- 재생 화면 오른쪽 가장자리의 **+**와 **-**로 재생 속도를 0.5배에서 2배까지 바꿉니다. 가운데 숫자를 누르면 1.0배로 돌아갑니다. 고른 속도는 앱을 다시 시작하기 전까지 다음 영상에도 이어집니다.
- 폴더를 추가하면 홈의 **폴더별 영상** 줄에 폴더 타일이 생깁니다. 타일을 누르면 그 폴더가 바로 열리고, 줄 제목을 누르면 보관함으로 갑니다. 그 폴더에서 최근에 연 영상이 있으면 타일에 장면을 흐리게 깝니다.
- 카드와 행을 누르면 지금처럼 바로 재생합니다. **영상 상세**는 대표 영상의 이어서 재생 옆, 계속 시청하기 카드 오른쪽 위, 최근 영상과 보관함 행 오른쪽 끝의 정보 아이콘으로 엽니다. 상세에는 길이, 수정한 날짜, 해상도와 형식, 본 만큼 채워지는 이어보기 버튼, 영상과 음성 형식, 용량을 보여 줍니다.
- 홈의 계속 시청하기 카드는 남은 시간을, 이어서 재생 버튼은 본 만큼 바탕을 칠해 보여 줍니다. 최근 영상 행의 재생 표시는 본 만큼 둘레가 채워집니다.
- 오른쪽 위 자물쇠로 화면을 잠급니다. 잠금 중 화면 터치와 뒤로 가기는 해제 버튼만 표시하며, 회전해도 잠금은 유지됩니다.
- 재생 화면 위쪽의 **자막**에서 영상에 들어 있는 자막을 고르거나 끌 수 있습니다. **외부 자막 열기**에서 SRT, SMI, VTT, ASS/SSA 파일을 선택합니다(최대 2 MiB). 인코딩은 UTF-8, UTF-16(BOM 있음)과 한국어 Windows에서 흔한 CP949(EUC-KR 포함)를 읽고, SMI에 여러 언어가 있으면 한국어로 시작합니다. 자막 메뉴에서 파일에 들어 있는 다른 언어로 바꿀 수 있고, 같은 영상과 자막을 다시 열면 선택한 언어가 복원됩니다. 폴더 목록에서 연 영상은 같은 폴더에서 이름이 같은 자막(`영화.srt`, 다음으로 `영화.ko.srt`처럼 한국어 표시가 붙은 파일, 그다음 다른 표시가 붙은 파일)을 찾아 자동으로 붙입니다. 같은 폴더에 다른 편의 영상이 있으면 그 편의 자막은 후보에서 뺍니다. 이 영상에서 자막을 한 번도 고르지 않았을 때만 붙이고, 끄거나 다른 자막을 고른 선택은 그대로 둡니다. 파일 하나만 골라 연 영상은 Android가 같은 폴더를 읽게 해 주지 않아 자동으로 찾지 못합니다. 자막은 0.1초씩 일찍 또는 늦게 표시할 수 있고, 외부 자막은 글자 크기도 바꿀 수 있습니다. 영상마다 선택과 설정을 기억합니다.
- **보관함**은 **폴더**와 **최근 본 영상** 두 탭으로 나뉩니다. 앱을 새로 켜면 폴더 탭이 먼저 보이고, 홈에 다녀오면 보던 탭으로 돌아옵니다. 홈의 **폴더별 영상** 제목은 폴더 탭을, **계속 시청하기**와 **최근 영상** 제목은 최근 본 영상 탭을 엽니다. 제목 검색은 최근 본 영상 탭에 있습니다.
- 폴더 탭 목록 끝의 **폴더 추가** 행에서 폴더를 선택합니다. 추가한 폴더는 폴더 탭에 행으로 보이고, 누르면 바로 열립니다. 폴더 목록의 영상 행은 보관함처럼 장면과, 본 적이 있으면 본 위치와 진행 정도를 보여 줍니다. 목록에서 하위 폴더로 들어가 영상을 재생할 수 있고, 재생을 닫으면 보던 폴더로 돌아옵니다. 폴더 맨 위에서 뒤로 가면 연 곳(보관함이나 홈)으로 돌아갑니다. 파일을 추가하거나 옮긴 뒤에는 **새로고침**을 누릅니다.

libVLC는 설치 후 처음 재생할 때 기기 글꼴 캐시를 만들고, 그동안 영상을 내보내지 않습니다. 그래서 앱을 켜면 이 캐시를 미리 만듭니다. 다 만들기 전에 영상을 열면 **처음 한 번만 글꼴을 준비하는 중**을 보여 주며 기다리고, 그 뒤에도 첫 장면이 나올 때까지 **영상을 여는 중**을 표시합니다. 가상 기기에서 이 준비에 4~27초가 걸렸고, 실제 휴대폰 확인은 남아 있습니다([QA-028](docs/qa-issues.md#qa-028-설치-직후-첫-영상이-0분-0초에서-오래-멈춤)).

2026-11-20 [자막 검증](docs/verification.md#2026-11-20-자막-선택과-표시)에서 Android 17 가상 기기로 한글과 영어 내장 자막 전환, 외부 한글 SRT 표시와 설정 복원을 확인했습니다. 실제 휴대폰 검증은 남아 있습니다.

2026-11-17 [화면 잠금 검증](docs/verification.md#2026-11-17-화면-잠금-검증)에서 디버그와 릴리스 빌드, 테스트 13개가 통과했습니다. Android 17 가상 기기에서 터치 재생, 잠금과 해제를 확인했습니다. Android Lint는 대상 SDK 관련 기존 오류 1건으로 실패했고, 이후 [Lint 처리 기준 변경](docs/verification.md#2026-11-17-대상-sdk-알림의-lint-등급-변경)에서 이 알림을 정보로 낮췄습니다. 원래 실패한 머신의 재검증은 남아 있습니다. 실제 휴대폰과 음성, 자막 재생은 이번 검증에 포함하지 않았습니다. 과거 실행 결과와 남은 검사는 [검증 기록](docs/verification.md), 결함 상태는 [QA 이슈](docs/qa-issues.md)에 있습니다.

## 개발 환경

- JDK 17
- Android SDK Platform 36
- Android SDK Build-Tools 36.0.0
- Gradle 8.14.3: 이 폴더의 `gradlew` 사용

이 폴더(`apps/video`)가 Gradle 빌드의 기준 폴더입니다. Android Studio에서도 저장소 루트가 아니라 이 폴더를 엽니다. Gradle 실행에 JDK 17을 사용합니다. `gradle/gradle-daemon-jvm.properties`도 17로 고정하며 JDK 자동 설치는 사용하지 않습니다.

SDK 위치는 `ANDROID_HOME` 또는 Git에서 제외한 `apps/video/local.properties`의 `sdk.dir`로 지정합니다. 전역 Gradle 설치는 필요하지 않습니다.

| 항목 | macOS | Windows |
|---|---|---|
| Gradle 실행 | `./gradlew` | PowerShell은 `.\gradlew.bat`, Git Bash는 `./gradlew` |
| SDK 기본 경로 | `~/Library/Android/sdk` | `%LOCALAPPDATA%\Android\Sdk` |
| ADB | `$ANDROID_HOME/platform-tools/adb` | `%ANDROID_HOME%\platform-tools\adb.exe` |

- `local.properties`는 Android Studio가 머신마다 만듭니다. 다른 운영체제의 사본에 복사하지 않습니다.
- `JAVA_HOME`이 JDK 17을 가리켜야 합니다. Android Studio에 포함된 JDK를 쓰면 터미널의 `JAVA_HOME`도 그 경로로 지정합니다.

## Android

앱 식별자는 `dev.forme.video`입니다. 최소 Android 버전은 8.0(API 26)이며, 빌드와 대상 SDK는 36입니다. `arm64-v8a`와 `x86_64`용 라이브러리를 포함합니다.

Gradle 모듈은 `:android`이고 폴더는 `apps/video/android`입니다.

### 자동 검사

`apps/video` 폴더에서 실행합니다.

```bash
./gradlew --no-daemon :android:lintDebug :android:testDebugUnitTest :android:assembleDebug :android:assembleRelease
```

- 코드 검사: Android Lint로 오류와 플랫폼 사용 문제를 확인합니다.
- 테스트: 재생 위치 저장과 복구 등 변경한 동작을 확인합니다.
- 앱 빌드: 디버그 APK와 서명하지 않은 릴리스 APK를 만듭니다. APK는 Android 앱 설치 파일입니다.

Lint 경고는 오류로 처리합니다. 새 라이브러리나 빌드 도구 버전이 나왔다는 알림 3종과 새 Android 버전이 나와 대상 SDK가 최신이 아니라는 알림(`OldTargetApi`)은 정보로 표시하며, 업데이트는 호환성을 확인한 뒤 반영합니다. 대상 SDK 상향은 그 SDK를 지원하는 Android Gradle 플러그인으로의 변경과 기기 검증을 함께 진행합니다.

기기에 설치할 파일은 `apps/video/android/build/outputs/apk/debug/android-debug.apk`입니다. 릴리스 파일은 `apps/video/android/build/outputs/apk/release/android-release-unsigned.apk`이며, 서명과 외부 배포는 수행하지 않습니다.

코드 검사 보고서는 `apps/video/android/build/reports/lint-results-debug.html`, 테스트 보고서는 `apps/video/android/build/reports/tests/testDebugUnitTest/index.html`에 생성됩니다.

재생기를 흉내 낸 테스트는 앱의 상태 처리를 확인하는 데 쓰고, libVLC의 실제 재생은 기기에서 확인합니다.

현재 로컬 테스트는 재생 위치 처리와 Room 데이터 보존, 파일 접근 실패를 검사합니다. Room과 파일 접근 테스트는 Android 동작을 개발 머신에서 재현하는 Robolectric을 사용합니다. 실제 시스템 권한과 기기 동작을 확인하는 검사는 아닙니다.

Room의 저장 구조는 `apps/video/android/schemas`에 남깁니다. 구조를 바꿀 때는 기존 기록을 보존하는 변환과 검사를 함께 추가합니다.

재생 중에는 약 2초마다 위치를 저장하고, 일시정지와 화면 종료 때도 저장합니다. 강제 종료나 전원 차단 직전의 위치까지 저장된다고 보장하지 않습니다. 실제 업데이트 검증에는 같은 서명 키를 사용해야 합니다.

### 버전

[시맨틱 버전](https://semver.org/lang/ko/)(주.부.수)을 씁니다. 버전은 `android/build.gradle.kts`의 `appVersion` 한 곳에서만 바꾸고, 보관함 맨 아래에 `버전 0.2.0`처럼 표시됩니다. 0.2.0부터 시작했습니다.

- 1.0.0 전까지: 새 기능이나 보이는 동작이 바뀌면 부 버전(0.2.0 → 0.3.0), 결함 수정만 있으면 수 버전(0.2.0 → 0.2.1)을 올립니다.
- 1.0.0: 아래 기기 검증의 기본 순서를 실제 휴대폰에서 통과하면 올립니다.
- Android 업데이트 순서 번호(`versionCode`)는 `주 × 10000 + 부 × 100 + 수`로 자동 계산합니다(0.2.0은 200). 이 번호가 작아지면 덮어 설치할 수 없으므로 버전을 낮추지 않습니다. 부와 수가 100 이상이거나 형식이 다르면 빌드가 멈춥니다.
- 휴대폰에 설치할 빌드를 만들 때 버전을 올리고, 개발 기록의 release와 검증 기록에 버전과 APK SHA-256을 함께 남깁니다.

### 기기 검증

실제 기기 검증은 갤럭시 S25에서 시작하고 두 번째 기기로 넓힙니다.

기본 순서는 다음과 같습니다.

설치 → 영상 재생 → 앱 종료 → 이어보기 → 업데이트 설치 → 이어보기 재확인

- 업데이트 전 버전에서 저장한 재생 위치와 파일 접근이 유지되는지 확인합니다.
- 기기 재시작, 권한 취소, 파일 이동과 삭제도 해당 변경에 맞춰 확인합니다.

세부 항목과 기록 형식은 [검증 기록](docs/verification.md)을 사용합니다.
