# 화면 녹화 GIF 생성기 화면 설계

[범위](scope.md)의 첫 사용 흐름을 화면으로 옮깁니다. 값은 개인 디자인 취향 원장(`~/dev/p/tools/taste`)에서 2026-11-14에 받은 기본값을 따릅니다.

2026-11-14 시제품은 선택 오버레이와 조작 막대를 구현했습니다. 자르기 창은 아직 없어, 정지하면 바로 저장하고 폴더를 엽니다. 화면을 띄워 확인하지 않았으므로 아래 동작은 아직 설계입니다.

## 구현 도구

- Tauri 2의 웹 화면은 React와 TypeScript로 만들고, 스타일은 Tailwind, 움직임은 CSS와 `motion`을 씁니다.
- 서체는 Pretendard Variable 하나로 제목과 본문을 씁니다. 앱이 인터넷 없이도 같은 글자를 보이도록 서체 파일을 앱에 넣습니다.
- 운영체제의 밝은 화면과 어두운 화면 설정을 따릅니다.

## 흐름과 화면

앱은 트레이 아이콘으로 상주하고, 녹화할 때만 화면이 나타납니다.

트레이의 녹화 → 선택 오버레이 → 조작 막대로 녹화 → 정지 → 자르기 창 → 저장 → 폴더 열림, 창 닫힘

### 선택 오버레이

- 화면 전체를 살짝 어둡게 덮습니다. 드래그하면 그린 사각형이 영역이 되고, 드래그 없이 창을 누르면 그 창이 대상이 됩니다. 마우스를 올린 창은 미리 밝게 드러납니다.
- 영역과 창을 고르는 전환 컨트롤은 두지 않습니다. 드래그와 클릭이라는 동작 차이로 나눕니다.
- 사용법 안내문은 두지 않습니다. 드래그 중에는 커서 옆에 영역의 너비와 높이만 보입니다.
- Esc를 누르면 취소합니다.

### 조작 막대

- 녹화 대상 바로 아래(공간이 없으면 위)에 뜨고, 녹화 결과에는 나오지 않습니다.
- 버튼은 정지와 취소 두 개입니다. 정지는 주 버튼, 취소는 보조 버튼입니다.
- 버튼 옆에 경과 시간을 보입니다. 초가 바뀔 때 숫자가 세로로 넘어갑니다.
- 트레이 메뉴에서도 같은 정지와 취소를 할 수 있습니다. 트레이 메뉴는 운영체제 기본 메뉴라 아래 화면 값의 적용 대상이 아닙니다.

### 녹화 범위 테두리

- 녹화하는 동안 녹화 대상 바로 바깥에 2px 테두리를 그립니다. 테두리가 녹화되는 내용을 가리지 않도록 바깥에 두고, 모니터 끝에 닿은 쪽만 안쪽으로 들어옵니다.
- 녹화 중이라는 상태 표시라 상태색(#e5484d)을 씁니다. 녹화 대상 화면 위에 그려지므로 밝은 화면과 어두운 화면 설정에 상관없이 같은 색입니다.
- 클릭을 아래 창으로 통과시키고, 녹화 결과에는 나오지 않습니다.
- 창을 녹화할 때는 0.1초마다 창 위치를 확인해 창이 움직이면 따라갑니다.

### 자르기 창

이 앱의 주 화면입니다. 화면 가운데의 녹화 미리보기가 지배적인 요소이고, 아래에 자르기 막대, 그 아래 한 줄에 품질 모드와 저장 버튼을 둡니다.

- 자르기 막대의 양 끝 손잡이를 끌면 미리보기가 그 시점의 화면으로 바로 바뀝니다. 녹화 길이와 자른 길이는 손잡이 근처에 숫자로만 보입니다.
- 품질 모드는 "기본"과 "품질" 두 항목의 세그먼트 컨트롤로 고릅니다. 고르면 그 옆의 예상 파일 크기가 새 값으로 넘어갑니다. GitHub 첨부 한도 10MB를 넘으면 크기 숫자를 상태색으로 표시합니다.
- 저장 버튼을 누르면 버튼 글자가 저장 중, 저장됨으로 바뀌고, 저장한 폴더가 열린 뒤 창이 닫힙니다. 폴더가 열려 결과가 보이므로 저장 완료 알림은 따로 두지 않습니다.
- 녹화를 버리는 동작은 창 닫기로 합니다. 다시 녹화 버튼은 범위에 근거가 없어 두지 않습니다.

## 화면 값

| 항목 | 값 |
|---|---|
| 바탕 | 밝은 화면 #f3f5f8, 어두운 화면 #101318 |
| 강조 | 색 없이 본문색. 밝은 화면 #1b1d22, 어두운 화면 #eceef2 |
| 상태색 | 크기 초과 같은 상태 표시에만 씀 |
| 서체 | Pretendard Variable. 본문 15px, 줄 간격 1.55. 제목 21px, 소제목 16px, 굵기 650 |
| 모서리 | 면, 버튼, 입력 6px |
| 간격 | 덩어리 사이 20px, 묶음 사이 28px. 선과 상자 없이 여백과 굵기로 나눔 |
| 주 버튼 | 높이 44px, 좌우 여백 18px, 글자 14px 굵기 600. 본문색 바탕에 표면색 글자 |
| 보조 버튼 | 투명 바탕, 1px 테두리, 본문색 글자 |
| 버튼 반응 | 올리면 120ms 동안 밝기 0.88, 누르면 120ms 동안 scale 0.95, 쓸 수 없으면 opacity 0.4 |
| 키보드 초점 | 버튼 테두리에 붙은 3px 옅은 번짐과 안쪽 1px 강조색 선 |
| 세그먼트 컨트롤 | 트랙 없이 고른 항목 아래 2px 밑줄. 밑줄은 한 노드로 200ms ease-out 이동 |

## 움직임

| 대상 | 움직임 |
|---|---|
| 조작 막대와 자르기 창 등장 | opacity 0, scale 0.97, blur 4px에서 220ms ease-out-cubic으로 선명하게. 사라질 때 같은 길을 같은 길이로 되돌림 |
| 경과 시간, 예상 파일 크기 | 늘면 새 숫자가 아래 10px에서 올라오고 이전 숫자는 위로 나감. 줄면 반대 방향. 200ms ease-out-quint로 겹쳐 교차 |
| 저장 버튼 글자 | 새 글자가 아래 6px에서 160ms 동안 올라오고, 이전 글자는 위 6px로 100ms 안에 빠짐. 버튼 폭 유지 |
| 저장 중 표시 | 300ms 안에 끝나면 표시 없이 바로 저장됨. 더 걸리면 표시하고 최소 400ms 유지 |
| 자르기 손잡이 | 끄는 동안 움직임 없이 바로 따라감 |

- 미리보기 화면은 움직임 없이 바로 보입니다. 장식 요소만 움직입니다.
- 운영체제의 움직임 줄이기 설정이 켜져 있으면 이동과 크기 변화를 생략합니다.

## 확인할 항목

- 조작 막대가 어두운 화면과 밝은 화면 위 어디에 떠도 경계가 보이는지
- 밝은 화면과 어두운 화면에서 본문 4.5:1, 큰 글자와 경계 3:1 대비
- 예상 파일 크기를 품질 모드를 바꿀 때마다 계산할 만큼 변환이 빠른지
- 서체 로딩, 깜빡임과 움직임의 체감은 화면을 띄워 확인

## 열린 질문

- 품질 모드를 녹화 전에 고를지, 지금처럼 저장 전에 고를지
- 저장 폴더를 바꾸는 자리. 범위의 "기본 저장 폴더와 폴더 변경 방법"을 정할 때 함께 정합니다.
