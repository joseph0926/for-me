# 갤러리 앱 검증 기록

기술 선택과 앱 동작을 확인한 기록입니다. 기술 선택의 근거는 [기술 조사](research.md)에 있습니다.

## 2026-11-28 미디어 관리 권한 가상 기기 최소 실험

[기술 조사의 최소 실험](research.md#착수-전-최소-실험) 네 단계를 Windows에서 확인했습니다. 사용자가 "실험 진행"을 골랐습니다. 저장소 밖 임시 폴더에 실험 앱과 실험 전용 가상 기기를 만들었고, 끝난 뒤 앱을 지우고 가상 기기도 지웠습니다. 기존 가상 기기 `Medium_Phone_API_37.0`은 건드리지 않았고, 앱 코드는 저장소에 남기지 않았습니다.

### 환경

- 가상 기기: Android 17(API 37) `google_apis_playstore` x86_64 이미지, 기기 정의 `medium_phone`, `google/sdk_gphone64_x86_64/emu64xa:17/CE2A.260420.051.A2/16418371`. 창 없이 실행했습니다. 이 PC에는 Android 14(API 34) 이미지가 없어 최소 버전인 Android 14에서는 시험하지 않았습니다.
- 앱: androidx 없이 프레임워크 API만 쓴 Java 앱. minSdk 34, compileSdk와 targetSdk 36, AGP 8.13.2, Build-Tools 36.0.0. 매니페스트에는 `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`, `READ_MEDIA_VISUAL_USER_SELECTED`, `MANAGE_MEDIA`만 두고 `READ_EXTERNAL_STORAGE`는 두지 않았습니다. `READ_EXTERNAL_STORAGE`를 더한 판도 만들었지만, 없는 판이 통과해 비교하지 않았습니다.
- 사진: Python으로 만든 320x240 PNG 6장을 `adb push`로 `Pictures/MMExp`에 넣고 미디어 스캔으로 등록했습니다(ID 18~23). 소유 앱은 `com.android.shell`이라, 실험 앱이 바꾸려면 승인이 필요한 상태입니다. 영상은 넣지 않았습니다.
- 판정: 요청마다 결과 코드, 요청부터 결과까지 걸린 시간, 결과 뒤의 `IS_TRASHED`와 `IS_FAVORITE`를 앱이 logcat에 남겼습니다. 확인 창은 요청 직후 화면 구조(`uiautomator dump`)에서 MediaProvider의 `PermissionActivity`와 "Allow MMExp to move this photo to trash?" 같은 문구로 확인했습니다.
- 읽기 권한의 전체 허용은 `pm grant`로 줬습니다. 부분 허용과 미디어 관리는 시스템 화면을 눌러서 켰습니다.

- 미디어 관리 켜기: `ACTION_REQUEST_MANAGE_MEDIA`로 연 설정 화면("Media management apps")에 실험 앱이 나왔고, "Allow app to manage media" 스위치를 누르자 `canManageMedia()`가 참이 됐습니다. `appops`에는 `MANAGE_MEDIA: allow`로 남았습니다. 화면 설명에는 "App must have permission to access files and media."라고 적혀 있습니다.
- `canManageMedia()`는 읽기 권한을 모두 회수해도, 부분 허용으로 바꿔도 참으로 남았습니다. 그래도 그 상태에서는 확인 창이 떴습니다. 이 값만으로 확인 창이 생략된다고 판단할 수 없습니다.
- 앱을 업데이트 설치해도 미디어 관리 권한은 켜진 채였습니다. 같은 버전 번호의 APK를 다시 설치한 것이며, 버전 번호를 올린 업데이트는 하지 않았습니다.
- 최근 삭제됨 조회(`QUERY_ARG_MATCH_TRASHED`를 `MATCH_ONLY`로): 전체 허용에서 휴지통에 넣은 20, 21이 나왔습니다. 기본 조회에서는 두 장이 빠졌습니다. 부분 허용에서는 고른 사진(18)을 휴지통에 넣었을 때 18만 나왔습니다.
- 확인 창이 떠 있는 동안 adb로 보낸 다음 요청은 실험 앱에 전달되지 않았습니다. 실제 앱에서는 확인 창이 화면을 가리므로 영향이 없을 것으로 봅니다(AI 해석).

### 판정

- 1단계 통과(Android 17): `READ_EXTERNAL_STORAGE` 없이 `READ_MEDIA_IMAGES`, `READ_MEDIA_VIDEO`만으로 미디어 관리를 켤 수 있었고, `canManageMedia()`가 참이 됐습니다.
- 2단계 조건부 통과: 전체 허용에서는 휴지통, 되돌리기, 즐겨찾기, 영구 삭제가 모두 확인 창 없이 끝났습니다. 부분 허용에서는 미디어 관리를 켜도 휴지통과 되돌리기에 매번 확인 창이 떴습니다.
- 3단계 통과: 확인 창에서 취소하면 `RESULT_CANCELED`가 오고 사진은 바뀌지 않았으며, 실험 앱 화면으로 돌아왔습니다.
- 4단계 통과: 휴지통 항목이 최근 삭제됨 조회에 나왔습니다.

### 앱 설계에 주는 점(AI 해석)

- 확인 창 없이 처리하고 5초 실행 취소를 보여 주는 조건은 "`canManageMedia()`가 참이고 사진과 영상 읽기가 전체 허용"입니다. 둘 중 하나라도 아니면 매번 확인 창 방식으로 처리합니다. 두 값 모두 화면에 돌아올 때 다시 확인합니다.
- 부분 허용 사용자에게 미디어 관리를 켜라고 안내해도 확인 창은 없어지지 않습니다. 안내는 전체 허용일 때만 보여 줍니다.
- 즐겨찾기는 이 기기에서 미디어 관리 권한과 관계없이 확인 창이 뜨지 않았습니다. 앱이 읽을 수 있는 사진이었다는 점이 공통입니다. 고르지 않은 사진의 즐겨찾기는 시험하지 않았습니다.

### 실행하지 못한 검사

- Android 14(API 34)와 다른 Android 버전: 이 PC에 이미지가 없습니다. 새 이미지 설치는 사용자 확인이 필요해 하지 않았습니다.
  - 후속(2026-11-28): 사용자가 "설치하고 실험"을 골라 Android 14를 [아래 기록](#2026-11-28-android-14-가상-기기-재실험)에서 시험했습니다.
- 실제 휴대폰(갤럭시 S25, A16): 제조사 설정 화면의 미디어 관리 메뉴 위치와 동작이 다를 수 있습니다.
- 영상 항목, 요청 2000개 초과, 이미 사라진 항목에 대한 요청, 고르지 않은 사진의 즐겨찾기
- 버전 번호를 올린 업데이트와 재부팅 뒤 권한 유지
- 시스템이 휴지통 항목을 기간 뒤 지우는 동작

## 2026-11-28 Android 14 가상 기기 재실험

[위 실험](#2026-11-28-미디어-관리-권한-가상-기기-최소-실험)에서 시험하지 못한 최소 버전 Android 14에서 같은 순서를 반복했습니다. 사용자 승인으로 Android 14 이미지를 설치했습니다. 실험 앱과 실험 전용 가상 기기는 다시 임시 폴더에 만들었고, 끝난 뒤 앱을 지우고 가상 기기를 지웠습니다. 앱 코드는 저장소에 남기지 않았습니다.

### 환경

- 설치: Android SDK의 `system-images/android-34/google_apis_playstore/x86_64` r14(약 3.1GB). 새 라이선스 동의는 필요하지 않았습니다. 다음 실험에 쓸 수 있게 이미지는 남겨 두었습니다.
- 가상 기기: Android 14(API 34), `google/sdk_gphone64_x86_64/emu64xa:14/UE1A.230829.036.A4/12096271`, 보안 패치 2023-09-05, 기기 정의 `medium_phone`. 실제 휴대폰은 MediaProvider가 Google Play 시스템 업데이트로 더 새 버전일 수 있습니다.
- 앱: 위 실험과 같은 Java 앱. `READ_EXTERNAL_STORAGE` 판은 빼고, 버전 번호(versionCode)를 1과 2로 달리한 APK 두 개를 만들었습니다.
- 사진: 같은 PNG 6장(ID 1000000017~1000000022, 소유 앱 `com.android.shell`). 판정 방법은 위 실험과 같습니다.

- 설정 화면은 Android 17과 같았습니다("Media management apps", "Allow app to manage media", 같은 설명 문구). `READ_EXTERNAL_STORAGE` 없이 켜졌습니다.
- 부분 허용을 고르는 권한 창의 버튼은 "Select photos and videos"였습니다(Android 17은 "Allow limited access"). 사진 선택 화면도 다르게 생겼고, 완료 버튼은 "Allow (1)"이었습니다.
- 최근 삭제됨 조회: 전체 허용에서 휴지통에 넣은 19, 20이 나왔고, 부분 허용에서는 고른 17만 나왔습니다.
- `appops set`으로 미디어 관리를 끄려면 `--uid`를 붙여야 했습니다. 설정 스위치는 uid 단위로 기록하므로, 패키지 단위 값만 바꾸면 `canManageMedia()`가 그대로 참입니다.
- `adb reboot` 뒤 권한이 사라진 원인은 확인하지 않았습니다. `adb reboot`는 시스템의 정상 종료 절차를 거치지 않을 수 있고, 앱 권한 기록은 바로 파일에 쓰지 않고 모아서 쓴다고 알려져 있습니다. 그래서 켠 직후의 기록이 저장되기 전에 꺼졌을 수 있다고 봅니다(AI 해석, 미확인). 사용자가 전원 메뉴로 재시작하는 경로에서는 유지됐습니다.

### 판정

- 1~4단계 모두 Android 17과 같은 결과입니다. 1, 3, 4단계는 통과, 2단계는 전체 허용에서만 통과입니다.
- 버전 번호를 올린 업데이트 뒤 권한 유지: 통과. 정상 재시작 뒤 권한 유지: 통과. 갑작스러운 재시작 뒤에는 권한이 꺼질 수 있습니다.

### 앱 설계에 주는 점(AI 해석)

- 즐겨찾기 요청은 두 버전 모두에서 권한과 관계없이 확인 창 없이 처리됐습니다. 미디어 관리 권한은 휴지통, 되돌리기, 영구 삭제에만 영향을 줍니다.
- 미디어 관리 권한은 재시작 뒤 꺼질 수 있습니다. 화면에 돌아올 때마다 다시 확인하고, 꺼졌으면 5초 실행 취소 대신 확인 창 방식으로 돌아갑니다. 처음 켰을 때만이 아니라 꺼진 것이 보일 때 다시 켜는 안내도 둡니다.
- 앱이 볼 수 없는 사진도 즐겨찾기를 바꿀 수 있고 휴지통 확인 창도 띄울 수 있습니다. 이 앱은 화면에 보인 항목만 요청하므로 문제는 없지만, 요청 전에 대상이 현재 목록에 있는지 확인합니다.

### 실행하지 못한 검사

- 실제 휴대폰(갤럭시 S25, A16)과 최신 MediaProvider
- 영상 항목, 요청 2000개 초과, 이미 사라진 항목에 대한 요청
- `adb reboot` 뒤 권한이 사라진 원인과, 켠 뒤 시간이 지나고 갑작스럽게 재시작했을 때의 유지
- 시스템이 휴지통 항목을 기간 뒤 지우는 동작
