# Viewgrain 검증 계획과 기록

원하는 화면을 고르고, AI에게 전달한 레퍼런스가 실제 구현에 반영되는지 확인합니다. 이미지 생성 품질과 MCP 전달 성공, 구현 결과를 따로 평가합니다.

## 첫 실험 제안

기존 앱의 구현 범위와 독립적으로 가장 매력적인 비디오 앱의 주 화면을 탐색하고, 선택한 방향의 재생 화면으로 확장합니다. 방향 수와 생성량을 먼저 고정하지 않으며, 실제 생성량과 비용은 실행 전에 정합니다.

1. [레퍼런스 탐색 방향](video-reference.md)에 따라 기존 앱의 기능, 콘텐츠와 배치를 제약으로 사용하지 않고 주 화면을 생성합니다.
2. 원하는 방향의 화면을 고른 뒤 재생 화면을 확장합니다. 정밀 비교가 필요하면 그때 콘텐츠와 화면 조건을 맞춥니다.
3. 사용자가 마음에 드는 목록과 재생 화면, 유지할 특징을 고릅니다. 하나도 마음에 들지 않으면 선택 없음으로 남깁니다.
4. AI가 MCP로 선택한 이미지와 설명을 가져옵니다.
5. 별도로 승인된 구현 작업에서 시안을 적용하고 기존 화면, 선택한 시안, 구현 결과를 비교합니다.

탐색 범위와 필요한 화면은 생성 결과를 보고 조정합니다. 자동 점수만으로 사용자 취향에 맞는다고 판정하지 않습니다.

## 실행할 때 남길 정보

- 시안의 식별자와 버전, 원본 이미지, 모델과 생성 설정, 실제 프롬프트
- 같은 조건으로 비교한 항목과 달라진 항목, 사용자의 선택과 이유
- MCP 서버와 AI 도구의 버전, 실행한 OS, 반환한 자료와 실패 여부
- 구현한 앱의 버전, 비교 화면, 반영된 특징과 남은 차이
- 생성량과 확인 가능한 비용. 알 수 없는 값은 미확인으로 표시합니다.

시안에 그려진 탐색 막대나 버튼은 실제 재생 동작의 증거가 아닙니다. 동영상 앱에 적용할 때는 해당 앱의 [검증 기준](../../video/docs/verification.md)을 별도로 따릅니다.

## 2026-11-17 문서화 시작

MCP 공식 규격과 공개 프롬프트 후보의 원문 및 라이선스를 확인했습니다. 세부 결과는 [자료 조사](research.md)에 있습니다.

문서화 시작 당시에는 갤러리와 MCP 실행, 시안 생성, 실제 앱 구현 비교를 수행하지 않았습니다. 이후 사용자 생성 결과와 선택은 아래 기록에 남겼습니다.

## 2026-11-17 첫 실험의 공통 조건 작성 기록

동영상 앱의 범위 문서와 현재 화면 코드를 확인해 목록과 재생 화면에 필요한 기능을 정리했습니다. 세로 목록과 가로 재생 화면의 크기, 가상 영상 3개의 제목과 재생 위치, 같은 장면 원본을 사용할 조건을 [공통 조건](video-reference.md)에 기록했습니다.

당시에는 썸네일을 현재 앱에 없는 제안 요소로 구분했습니다. 이후 이 조건에 맞춘 프롬프트를 작성했지만, 사용자가 기존 앱의 제약 없이 최고의 비디오 앱 레퍼런스를 탐색하도록 정정했습니다. 이전 조건은 현재 탐색에 적용하지 않습니다.

## 2026-11-17 첫 레퍼런스 묶음 등록

사용자가 금색 강조색과 하단 메뉴 및 버튼 표현을 지적한 뒤, 수정한 홈과 세로 재생 및 가로 재생 세 장에 만족을 표시했습니다. 원본을 [SCENE 버전 1](../references/scene-001/v1/README.md)로 보관하고, [프롬프트 활용 문서](prompt-guide.md)에 탐색과 수정 과정을 반영했습니다.

원본과 복사본의 바이트 및 SHA-256 일치, PNG 구조와 이미지 크기, 메타데이터의 식별자와 경로, 문서 링크와 한국어 표기를 확인했습니다. 홈과 세로 재생은 941 × 1672픽셀, 가로 재생은 1672 × 941픽셀입니다. 파일 원본을 변환하거나 수정하지 않았습니다.

재생 장면과 시간이 수정 과정에서 달라졌으므로 색과 조작부만 바뀐 통제 실험으로 판정하지 않습니다. 실제 생성 모델과 입력 전문, 가로 확장 프롬프트, 비용은 미확인입니다. 작은 기기에서의 가독성, 실제 재생, 앱 업데이트 후 보존, 갤러리와 MCP 전달 및 구현 비교는 수행하지 않았습니다.

## 2026-11-17 FRAME 컬렉션 상세 선택

사용자가 추가 수정한 목록형 결과를 `2번으로`라고 선택했습니다. [FRAME 버전 1](../references/frame-002/v1/README.md)에 해당 원본 한 장과 P05부터 P07까지의 요청을 보관했습니다. P07은 사용자가 실제 추가 입력이라고 보고했으며 전체 입력 기록과 생성 모델은 미확인입니다.

원본과 복사본의 바이트 및 SHA-256 일치, PNG 구조와 크기 941 × 1671픽셀, 메타데이터와 문서 링크를 확인했습니다. 홈의 최종 선택, 재생 화면, 실제 기기의 가독성과 MCP 전달은 이번 검증에 포함하지 않았습니다.

## 2026-11-17 읽기 전용 MCP 구현과 실제 소비 검사

환경은 macOS 27.2.1 arm64, Node.js 24.22.2, Corepack 0.36.0, pnpm 12.16.1, 공식 서버 및 클라이언트 SDK 2.4.0, Codex CLI 0.169.0입니다. 서버 버전은 0.1.0입니다.

### 자동 검사

`corepack pnpm test`의 네 테스트가 통과했습니다.

- 실제 stdio 프로세스에서 두 도구를 발견하고 선택 이미지 네 장의 MIME 형식, 원본 SHA-256 일치와 선택 기록을 확인했습니다. 다른 작업 디렉터리에서 시작해도 자료를 찾았습니다. 조회 전후 원본 이미지, manifest, 설명과 프롬프트 기록을 비교했습니다.
- 누락 및 변조 이미지, 4 MiB 초과, 폴더 밖과 내부 파일을 가리키는 심볼릭 링크를 거부했습니다.
- 읽기 권한 거부를 누락과 구분했습니다.
- 잘못된 버전과 ID, 임의 경로, 입력 형식, 손상된 manifest와 중복 이미지 ID를 거부했습니다.

기존 node_modules가 없는 임시 사본에서 `corepack pnpm install --frozen-lockfile --ignore-scripts --offline`과 `corepack pnpm test`를 실행했습니다. 설치와 검사가 통과했습니다. 별도 빌드, CI와 릴리스 명령은 없습니다. 최종 소스의 무결성 검사와 경로 검사를 임시 사본에서 각각 제거했을 때 테스트가 실패했고, 복원 뒤 네 테스트가 다시 통과했습니다.

### 실제 Codex 이미지 인식

두 개의 독립적인 일회성 Codex 세션을 사용했습니다. 기존 사용자 설정을 제외하고 실행 인자로 이 서버만 지정했으며 영구 MCP 설정은 바꾸지 않았습니다. 각 세션에서 MCP 조회 한 번만 허용하는 요청을 보냈고 완료된 도구 호출 기록을 검사했습니다. 파일 직접 읽기, shell, 별도 이미지 열기와 웹 조회는 없었습니다.

- FRAME `frame-002-collection-list`, 버전 1, `include_context=false`: 이미지와 식별 정보만 전달했습니다. 모델은 영화 8개 행, 왼쪽 썸네일, 오른쪽 원형 재생 버튼과 상단의 뒤로 가기, 북마크, 더보기 순서를 읽었습니다. 원본과 일치합니다.
- SCENE `scene-001-player-landscape`, 버전 1, `include_context=true`: 기본 설명 결합 응답을 전달했습니다. 모델은 진행 막대 흰색 구간이 여성 얼굴 왼쪽에서 끝나는 점, 오른쪽 배경 남성, 하단 왼쪽의 일시정지, 10초 뒤로, 10초 앞으로 순서를 읽었습니다. 원본과 일치합니다. 설명도 전달된 조건이므로 텍스트 없는 첫 사례와 증거 범위를 구분합니다.

원본 바이트 일치는 공식 SDK 통합 검사에서 확인했습니다. Codex JSONL 로그는 도구 결과를 텍스트 JSON으로 감싸고 이미지 데이터를 중간 생략하므로 이 로그 자체에서 원본 해시를 다시 계산하지 않았습니다. 응답 메타데이터의 해시 일치와 실제 시각 답변을 별도로 확인했습니다. 도구 호출과 답변을 요약한 [검사 근거](evidence/mcp-cli-2026-11-17.json)에 환경, 입력, 반환 크기 및 해시와 관찰을 남겼습니다. 이미지 데이터와 세션 식별자는 중복 저장하지 않았습니다.

첫 CLI 실행은 바깥 샌드박스의 app-server 초기화 권한 거부로 시작하지 못했습니다. 승인 후 바깥 샌드박스 밖에서 다시 실행했고, 검사 대상 Codex 세션은 읽기 전용을 유지했습니다. 각 시각 사례는 한 번씩 확인했으므로 반복 안정성을 주장하지 않습니다.

### 남은 범위

SCENE 홈과 세로 재생 이미지는 바이트 전달까지 검사했고 모델의 시각 인식은 별도로 검사하지 않았습니다. Windows, 다른 AI 앱과 현재 대화의 도구 등록, HTTP, 갤러리와 검색, 실제 앱 구현 효과는 미검증입니다. 사용한 모델의 정확한 식별자는 별도로 기록하지 못했으므로 CLI 기본값으로 표시했습니다. 보관 시점의 manifest 검증 플래그는 변경하지 않았으며 실제 소비 성공 범위는 이 실행 기록이 소유합니다.

## 2026-11-17 리뷰 결함 두 건 수정

사용자 리뷰에서 특수 파일 조회 대기와 목록 및 상세 조회의 ID 길이 불일치가 발견됐습니다. 기존 네 테스트가 통과한 상태에서 놓친 조건이며, 최초 보고는 [QA 이슈](qa-issues.md)에 보존했습니다.

수정 전에 새 회귀 테스트 두 개를 실행했습니다. FIFO 이미지 조회는 요청 제한 2초를 초과했고, 151자 ID의 목록 거부 검사는 목록이 성공 응답을 반환해 실패했습니다. 테스트가 실제 결함을 검출하는 것을 확인한 뒤 수정했습니다.

- 파일을 열기 전에 일반 파일인지 검사하고, 비차단 옵션으로 연 뒤 다시 검사합니다. 이미지와 manifest, README 및 프롬프트 파일에 대해 실제 FIFO로 바꾼 임시 사본에서 각각 두 번 거부를 확인했습니다. 파일을 복원한 뒤 같은 서버의 정상 조회도 확인했습니다.
- 목록 검사와 MCP 입력 스키마가 식별자 문자 및 길이 정의를 공유합니다. 실제 목록 응답에 있는 150자 ID를 그대로 상세 조회해 이미지가 반환되는지 확인했고, 151자 ID는 목록부터 `INVALID_MANIFEST`로 거부됐습니다.

`corepack pnpm test`에서 기존 네 개와 회귀 테스트 두 개, 총 여섯 개가 통과했습니다. 선택 이미지 네 장과 기록의 보존 검사도 통과했습니다. 기존 생성 모델 인식 결과는 이번 수정의 재검증으로 간주하지 않습니다. 모델 이미지 인식, 다른 OS와 파일 종류가 검사 사이에 교체되는 경쟁 상황은 이번에 재검증하지 않았습니다. 새 패키지와 빌드 및 배포 설정은 추가하거나 변경하지 않았습니다.
