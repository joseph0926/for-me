# 실제 동작 검사

앱 빌드와 SHA-256, macOS와 Terminal 버전, CPU, 입력기를 함께 기록합니다. 사용자 명령어나 출력 내용은 증거로 수집하지 않습니다. 실패 시 처음 결과를 보존하고 수정 빌드의 재검증을 별도로 기록합니다.

## 웹 주소 클릭과 앱 업데이트

- 클릭 검사를 사용자에게 요청할 때는 같은 주소를 아래처럼 단독 줄과 문장 속에 한 번씩 넣습니다. 두 줄 모두 주소의 첫 글자와 끝의 `#section`을 Command 클릭하면 같은 전체 주소가 열려야 합니다. 두 번째 줄의 닫는 괄호나 바로 뒤의 조사 `을`을 클릭하면 열리지 않아야 합니다.

  ```text
  https://example.org/guide#section
  문서 주소 (https://example.org/guide#section)을 다시 확인하세요.
  ```

- 업데이트 뒤 macOS 앱 검색에서 TermKeys를 찾아 각 결과의 경로를 확인합니다. 설치본 `~/Applications/TermKeys.app`은 보여야 하고, 업데이트 때 설치 명령이 출력한 백업 경로는 보이지 않아야 합니다. 빌드 원본 `build/TermKeys.app`이 함께 보여도 이 검사는 통과합니다.
- 복원은 별도 테스트 계정에서 같은 업데이트를 거친 뒤 확인합니다. [복원 절차](../README.md)에 따라 백업을 다른 폴더에 `TermKeys.app`으로 복사하고 그 복사본으로 설치한 뒤, 설치된 앱의 버전이 업데이트 전과 같은지 확인합니다.

## 현재 0.2.1 단축키 등록 방식

0.2.1에서는 메뉴 열기와 닫기 시 단축키 등록이 해제되고 복구되는지도 확인합니다. 메뉴 감시 실패와 접근성 오류 주입은 자동 검사에서 확인하며, 실제 응답 지연 조건은 별도로 기록합니다.

1. 손쉬운 사용 권한이 없는 상태에서 `permission-required`와 단축키 미등록을 확인합니다. 업데이트로 권한을 다시 허용해야 할 수 있습니다.
2. 보안 키보드 입력을 켠 채 기본 터미널의 일반 입력 영역을 선택합니다. `registered`와 `보안 입력: 켜짐`을 확인합니다. 이 단계는 등록 확인일 뿐입니다.
3. 입력 줄의 `abcdef` 앞뒤에 Command 좌우 방향키를 사용해 X와 Y를 넣습니다. Enter는 누르지 않습니다. 결과가 `XabcdefY`인지 직접 확인하고 Ctrl+C로 취소합니다. 단축키 통지와 전송 요청 횟수가 각각 증가하는지도 확인합니다.
4. 같은 입력 검사를 다시 수행해 재현성을 확인합니다. 보안 입력이 꺼진 상태의 결과는 따로 기록합니다.
5. 다른 앱, Terminal 검색창과 설정창에서 단축키가 원래대로 동작하는지 확인합니다. 빠른 앱 전환, 메뉴 열기, 왼쪽과 오른쪽 Command, Shift와 Option 조합도 확인합니다.
6. `off` 이후에는 단축키를 예약하지 않아야 합니다. `on`을 반복해도 프로세스가 중복되지 않아야 합니다.
7. 권한 회수 후 등록 해제와 재허용 후 복구, 로그아웃 후 자동 실행, 절전 복귀, Terminal 재실행을 확인합니다. 한글과 여러 줄 입력, 긴 줄과 키 반복도 별도 항목으로 기록합니다.
8. 검사한 빌드별로 결과를 남깁니다. 다른 버전의 통과 결과를 현재 빌드의 결과로 옮기지 않습니다. 통지 횟수와 전송 요청 횟수만으로 실제 커서 이동을 판정하지 않습니다.

### 남은 메뉴 검사: QA-002

이 검사는 사용자가 나중에 하기로 했으며 아직 통과하지 않았습니다. 재개할 때는 입력 줄 이동 검사와 분리합니다.

1. `termkeys status`의 버전, PID, 통지 및 전송 요청 횟수를 기록합니다.
2. 터미널의 셸 메뉴를 열고 메뉴가 열린 상태에서 Command 왼쪽과 오른쪽을 한 번씩 누릅니다. Esc로 메뉴를 닫습니다. 이 사이 입력 줄에서는 두 단축키를 쓰지 않습니다.
3. `termkeys status`로 같은 PID인지와 두 횟수가 늘지 않았는지 확인하고 메뉴의 실제 동작도 기록합니다. 프로세스가 바뀌었거나 다른 입력이 섞였으면 이 비교로 판정하지 않습니다.
4. 메뉴를 닫은 뒤의 줄 이동은 별도 검사로 수행해 등록 복구를 확인합니다.

### 남은 응답 지연 검사: QA-003

실제 Terminal이 응답하지 않는 조건에서 앱 전환 후 단축키가 해제되는지와 지연 시간을 확인해야 합니다. 자동 검사에서 50ms 뒤 오류를 반환하도록 흉내 낸 결과는 이 검사를 대신하지 않습니다. 사용자 작업에 영향을 주므로 실행 조건과 시점을 맞춘 뒤 별도 검사 세션에서 확인하며, 현재는 미검증입니다.

## 0.1.0 입력 감시 방식의 검사 절차

아래는 중단한 방식의 과거 검사 절차입니다. 0.2.1에는 적용하지 않습니다.

1. `on` 실행 후 권한을 허용하지 않은 상태에서 `status`가 `permission-required`인지 확인합니다. 터미널 입력은 그대로 동작해야 합니다.
2. TermKeys의 손쉬운 사용 권한을 허용하고 `ready`인지 확인합니다. 필요하면 `off` 후 `on`을 실행합니다.
3. 새 Terminal 창에 실행하지 않을 `abcdef`를 입력합니다. `⌘←` 뒤 `X`, `⌘→` 뒤 `Y`를 입력해 `XabcdefY`가 되는지 확인합니다. Enter는 누르지 않고 입력을 취소합니다.
4. 왼쪽과 오른쪽 Command, 키 반복, Command를 먼저 놓는 순서, 한글 입력, 여러 줄 입력, 화면 폭으로 접힌 긴 줄을 확인합니다.
5. 일반 방향키와 Shift, Option, Control이 추가된 조합, 다른 앱, Terminal 검색창과 설정창에서 기존 동작이 유지되는지 확인합니다.
6. 보안 키보드 입력을 직접 켠 상태에서 원래 입력이 유지되고 `secure-input`으로 표시되는지 확인한 뒤 원래 설정으로 복구합니다.
7. 손쉬운 사용 권한 회수 후 변환이 중지되고 권한 대기로 바뀌는지 확인합니다. 재허용 후 복구도 확인합니다.
8. `on`을 두 번 실행해 PID가 유지되는지 확인합니다. `off`를 두 번 실행해 꺼짐 상태가 유지되는지 확인합니다.
9. `on` 상태에서 로그아웃과 로그인, 절전 복귀, Terminal 종료와 재실행 후 확인합니다. `off` 후에는 다음 로그인에서도 꺼져 있어야 합니다.
10. Vim과 tmux 등에서 Control 조합이 다른 의미임을 확인합니다. 셸 외 프로그램은 지원 완료로 표시하지 않습니다.

로그아웃, 재부팅과 권한 설정은 사용자 작업에 영향을 주므로 실행 시점을 사용자와 맞춥니다. 이 검사 때문에 기존 셸 설정이나 터미널 설정을 초기화하지 않습니다.
