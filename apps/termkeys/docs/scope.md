# 범위

사용자가 기본 터미널에서 Command와 좌우 방향키로 입력 중인 줄의 처음과 끝으로 이동하려고 요청했습니다. 기본 설정 화면의 보조키 목록에 Command가 없음을 사용자가 확인했고, 전용 프로그램 제작을 선택했습니다.

## 현재 범위: 0.2.1

- `⌘←`는 `Ctrl+A`, `⌘→`는 `Ctrl+E`로 바꿉니다.
- 메뉴 막대 아이콘 없이 로그인한 사용자의 세션에서 실행합니다.
- `on`, `off`, `status`로 실행과 자동 실행을 제어합니다.
- 권한 대기, 단축키 등록 여부와 보안 키보드 입력 상태를 각각 표시합니다. 보안 입력을 켠 상태에서도 두 단축키의 등록과 이동 요청을 수행합니다.
- 기본 터미널의 일반 창에서 입력 영역을 확인한 경우에만 두 단축키를 등록합니다. 다른 앱과 검색 입력칸, 메뉴에서는 등록을 해제하도록 구현합니다.
- 초점과 창 변경, 메뉴 열기와 닫기 알림 중 하나라도 등록에 실패하면 단축키를 등록하지 않습니다.
- 접근성 속성을 조회할 때마다 해당 객체에 50ms 대기 제한을 설정합니다. 설정 또는 조회 실패 시 중단하며, 전체 처리 시간이 50ms 이내라는 보장은 아닙니다.
- 기존 터미널 프로파일, 키 설정, 셸 설정 파일을 변경하지 않습니다.

## 완료 기준

빌드와 자동 검사에 더해 실제 Terminal에서 이동, 다른 앱과 입력칸 보존, 권한 거절과 회수, 보안 키보드 입력, 로그아웃 후 자동 실행을 확인해야 동작 검증 완료로 표시합니다. 실행하지 않은 검사는 미검증으로 남깁니다.

## 제외

Vim, tmux, 원격 셸과 모든 터미널 내부 프로그램의 키 설정 통일, Shift 선택 확장, App Store 배포, Windows와 Linux 지원은 포함하지 않습니다.

## 0.2.0 실험

0.1.0의 입력 감시 방식이 보안 입력 환경에서 막혀, 0.2.0에서 두 단축키를 시스템에 직접 등록하는 방식으로 바꿨습니다. 보안 입력 중 줄 이동과 터미널 검색창 및 다른 앱의 기존 동작 유지를 실제로 확인했습니다. 등록 성공과 실제 커서 이동 성공은 구분하며 0.1.0의 실패 기록은 보존합니다.

## 0.2.1 보완과 남은 검증

메뉴 감시 실패 처리와 접근성 객체별 대기 제한을 보완했습니다. 보안 입력 중 줄 이동은 0.2.1에서도 확인했습니다. 메뉴에서 단축키를 가로채지 않는지 분리해서 확인하는 검사는 사용자가 나중에 하기로 했고, 실제 Terminal이 응답하지 않는 조건도 미검증입니다. 다른 앱과 검색창의 실제 검증은 0.2.0 결과입니다. 세부 결과와 나머지 미검증 항목은 [검증 기록](verification.md)을 따릅니다.
