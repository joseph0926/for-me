# 범위

## 2026-11-18 처음 범위

사용자 요청과 후속 답변은 [사용과 개발 기록](../../journal/README.md)의 `today-ref` 요청에 원문으로 있습니다.

- 시작: 사용자가 대화에서 "오늘의 레퍼런스"라고 말할 때. 정해진 시각의 자동 실행은 하지 않습니다.
- 주제: 하루에 웹이나 앱 하나. 웹과 앱을 번갈아 고르고 같은 종류의 제품을 반복하지 않습니다.
- 수집: 실제 제품과 사용자가 정한 레퍼런스 사이트의 무료 공개 범위. 캡처는 로컬에만 두고 저장소에는 링크와 직접 쓴 설명만 둡니다.
- 선택: 하나로 결정하거나 여러 개를 조합합니다. 조합에서 가져올 부분이 비어 있으면 AI가 나눠 제안하고 사용자가 확정합니다.
- 완성작: 주제마다 독립 프로젝트. 서버 없이 가짜 데이터로 주요 동작이 실제로 움직이는 수준. 앱 주제는 휴대폰 크기 틀 안에 그립니다.
- 저장: 사용자가 완성이라고 하면 상태를 완성으로 바꿉니다. 커밋은 사용자가 합니다.

### 완료 기준

- 갤러리에서 주제를 고르고, 레퍼런스 캡처를 크게 보고, 하나 또는 여러 개를 골라 선택 문장을 복사할 수 있습니다.
- 잘못된 주제 파일이 있어도 나머지 주제가 갤러리와 검사 명령에 나옵니다.
- 첫 주제를 실제로 수집해 사용자가 레퍼런스의 질을 받아들이는지 확인합니다. 보관과 자동화를 넓히는 일은 그 뒤에 정합니다. Viewgrain에서 보관할 자료가 받아들여지기 전에 보관 기능부터 넓혔던 [폐기 기록](../../../docs/retired-viewgrain.md)의 교훈입니다.

## 2026-11-18 변경: AI가 고르기

사용자가 "당신이 판단하고 고르는걸 메인으로 가져갑시다"라고 정했습니다. 같은 날 AI가 사용자 역할로 세 주제를 돌린 방식을 기본으로 삼습니다.

- 선택: AI가 레퍼런스를 비교해 하나로 결정하거나 조합하고, 가져올 부분까지 정합니다. 사용자 확인을 기다리지 않습니다.
- 피드백: AI가 완성작을 직접 써 보고 결함을 한 번 고칩니다.
- 저장: AI의 확인이 끝나면 완성으로 저장하고 보고합니다. 사용자가 아직 보지 않았다는 사실은 기록에 남깁니다.
- 사용자는 선택 대기 중에 갤러리에서 선택 문장을 복사할 수 있습니다. AI가 선택을 확정하면 갤러리는 그 결과를 보여 줍니다. 제작 중이거나 완성된 뒤에도 사용자는 대화로 레퍼런스를 다시 지정하거나 피드백할 수 있고, AI는 그것을 따릅니다.
- 위의 처음 범위 중 선택과 저장 항목은 이 변경으로 대체됩니다.
