## 처리 기준

- 데이터나 권한 손상은 긴급, 핵심 기능 불가나 반복 실패는 높음, 우회 가능한 불편은 보통으로 둡니다.
- 상태는 확인 필요, 수정 대기, 수정 중, 재검증 대기, 완료, 보류 중 하나입니다. 보류하면 이유와 다시 볼 조건을 남깁니다.
- 고친 코드에서 원래 조건과 영향받는 동작을 확인한 뒤 완료로 바꿉니다. 결함이 아니거나 중복이면 완료 사유와 해당 번호를 남깁니다.

### QA-004 안내된 폴더에서 복사한 실행 명령이 경로를 두 번 붙인다

- 상태: 재검증 대기
- 우선순위: 보통
- 발견일: 2026-11-19 코드 리뷰, 사례 `2026-11-19-for-me-today-ref-run-dir`
- 영향: README의 작업 폴더에서 복사한 명령으로 완성작을 실행할 수 없다.
- 기대 동작: 갤러리를 실행한 폴더의 다른 터미널에 붙이면 해당 완성작이 시작된다.
- 재현: 기존 명령은 apps/today-ref에서 --dir apps/today-ref를 한 번 더 적용했다. 중첩된 경로가 없다.
- 증거: [topics.ts](../gallery/src/topics.ts), [README.md](../README.md). runCommand의 작업 폴더를 README의 실행 위치와 대조했다.
- 원인: runCommand가 저장소 루트에서 시작한다고 가정했다.
- 다음 조치: 지정된 Node와 pnpm 및 프로젝트 의존성이 갖춰진 환경에서 갤러리의 명령을 복사해 개발 서버 시작을 확인한다.
- 수정: 명령에서 중복된 작업 폴더 지정을 제거하고 복사 버튼 옆에 실행할 폴더를 표시했다.
- 재검증: 2026-11-19, topics.ts SHA-256 앞 12자리 e97d4fb909bb. 앱 폴더에서 runCommand가 낸 명령 6개의 선택 대상과 dev 스크립트를 실제 완성작의 package.json과 대조했다. 브라우저 복사와 서버 시작은 미확인이다.

### QA-005 한 주제를 읽지 못하면 나머지 주제까지 검사가 중단된다

- 상태: 완료
- 우선순위: 높음
- 발견일: 2026-11-19 코드 리뷰, 사례 `2026-11-19-for-me-today-ref-file-read`
- 영향: 어느 주제가 정상인지까지 확인할 수 없게 된다.
- 기대 동작: 오류를 해당 주제에 표시하고 나머지 주제를 검사한다. 실패가 있으면 명령은 종료 코드 1을 반환한다.
- 재현: 정상 주제와 topic.json이 디렉터리인 주제를 함께 넣자 EISDIR로 전체 검사가 중단됐다. 수정 전 추가한 회귀 검사도 같은 위치에서 실패했다.
- 증거: [check.ts](../scripts/check.ts), [topic.test.ts](../test/topic.test.ts). checkWorkspace가 readTopicFile을 호출하는 경로에서 예외가 발생했다.
- 원인: readFileSync에서 나온 예외가 주제별 결과를 만드는 코드까지 전달되지 않았다.
- 다음 조치: 해당 없음
- 수정: 주제 파일과 캡처를 읽을 때 생기는 오류를 해당 항목에 기록한다. 누락된 캡처는 경고로 처리한다.
- 재검증: 2026-11-19, check.ts SHA-256 앞 12자리 7e157b39d930. 실제 검사 명령에 정상 파일, 디렉터리, 누락 파일, 읽기 권한을 없앤 파일을 함께 넣어 1개 통과와 3개 실패, 종료 코드 1을 확인했다. 정상 주제만 넣으면 종료 코드는 0이다. 캡처가 디렉터리여도 다음 캡처의 검사 결과가 남는 회귀 검사를 포함해 13개가 통과했다.
