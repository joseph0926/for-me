# for-me 기록

개발 AI가 요청과 수정, 검사 결과를 기록하고 웹에서 사용과 발전 과정을 확인하는 로컬 도구입니다. 기존 세 앱은 사용 상태와 시작 이유를 미확인으로 등록합니다. 저장소 문서가 없어져도 기록은 남습니다.

## 실행

Node.js 24 이상을 사용하며, 개발 버전은 저장소 루트와 이 폴더의 `.node-version`이 정합니다. 외부 패키지 설치나 빌드가 필요하지 않습니다. 저장소 루트에서 실행합니다.

```sh
node apps/journal/src/server.mjs
```

브라우저에서 `http://127.0.0.1:4318`을 엽니다. 현재 컴퓨터의 연결만 받습니다. 종료는 터미널에서 Ctrl+C입니다.

다른 위치에 기록을 보관하거나 다른 저장소 사본과 연결할 수 있습니다.

```sh
node apps/journal/src/server.mjs --data-dir /absolute/private/journal-data --repo-root /absolute/for-me --port 4318
```

Windows에서는 경로를 해당 머신의 절대 경로로 바꿉니다. 두 머신이 동시에 같은 파일을 공유하는 동기화 기능은 없습니다. 브라우저와 CLI는 반드시 같은 `--data-dir`을 사용해야 합니다.

## 기록하기

- 앱을 선택하고 기록 남기기에서 한 줄을 저장합니다. 날짜는 사용자가 보고 있는 컴퓨터의 오늘을 기본값으로 사용합니다.
- 사용, 불편과 요청, 변경, 검증, 버전, 후속 사용, 만든 이유를 구분합니다. 원문, 출처, 측정 구분과 버전은 추가 항목에서 입력합니다.
- 앱마다 입력 안내가 다릅니다. GIF 결과 활용처럼 단순 사용 횟수로 알 수 없는 경험을 남깁니다.
- 후속 기록으로 이전 요청이나 변경에 연결합니다. 상태가 완료인 요청도 AI 해석과 실제 확인 결과를 함께 읽어야 합니다.
- 첫 시작 이유는 상세 화면에 남고, 방향 변화는 새 기록으로 덧붙입니다. 과거에 만든 앱은 회고로 작성했다는 사실을 내용에 적습니다.
- 앱 정보 수정에서 이름과 폴더, 사용 상태를 바꿀 수 있습니다. 앱 ID는 유지합니다. 사용 상태 변경에는 이유가 필요합니다.
- 최근 7일, 최근 30일 또는 전체 기간의 기록을 봅니다. 집계는 실사용 기록만 사용량에 포함하며 실측과 추정을 나눕니다. 기록이 없는 날은 사용 0회를 뜻하지 않습니다.
- 수정은 이력에 남고 사용자 원문은 덮어쓰지 않습니다. 원문 정정은 후속 기록으로 남깁니다. 휴지통 항목은 복원할 수 있습니다.

브라우저 초안은 해당 브라우저의 로컬 저장소에 있습니다. 기록 원본과 다른 보관 위치이며 브라우저 데이터를 지우면 초안은 사라집니다. 저장 실패 시 입력을 유지합니다. 다른 창이나 AI가 먼저 저장했다면 최신 내용을 확인한 뒤 다시 저장합니다.

## AI 연결

개발 AI는 [기록 절차와 명령 계약](docs/agent.md)을 따릅니다. 별도 AI 서비스나 API 키가 필요하지 않습니다. 이 CLI를 호출하는 개발 AI만 기록에 참여하며, 모든 대화를 감시하거나 과거 대화를 자동 수집하지 않습니다.

```sh
node apps/journal/src/cli.mjs init
node apps/journal/src/cli.mjs read
node apps/journal/src/cli.mjs connections
```

쓰기 명령은 `node apps/journal/src/cli.mjs write`의 표준 입력으로 JSON을 전달합니다. 같은 명령의 재시도는 동일한 `operationId`를 사용합니다. 서버가 실행 중이지 않아도 CLI는 동일한 저장 계약으로 동작합니다.

## 보관과 백업

기본 저장 위치는 `apps/journal/data/journal.json`이며 Git에서 제외됩니다. 이 파일은 사용자가 직접 수정하는 입력 형식이 아닙니다. 웹이나 CLI로만 변경합니다.

- 백업 받기는 변경 이력과 중복 방지 정보가 포함된 JSON을 내려받습니다. 별도 장소에도 보관하세요.
- 백업 복원은 형식을 검증하고 현재 기록을 백업의 내용으로 바꿉니다. 복원 직전 기록은 변경 이력의 `backup.restore` 항목에 보존됩니다. 이를 웹에서 되돌리는 전용 기능은 없으므로 복원 전 백업 받기를 권합니다.
- 내보내기는 선택한 앱과 기간의 기록을 Markdown으로 받습니다. 전체 데이터 백업을 대신하지 않습니다.
- 앱 업데이트는 데이터 폴더를 지우지 않고 실행 파일만 바꿉니다. 저장 형식 1을 사용하며 지원하지 않는 형식이나 손상된 파일을 자동 초기화하지 않습니다.
- 쓰기는 임시 파일을 디스크에 반영한 뒤 이름을 바꿔 교체합니다. 요청 전체를 직렬화하고 revision 충돌을 거절합니다. 전원 손실과 파일 시스템 고장에 대한 완전한 보장은 아니므로 별도 백업이 필요합니다.
- 원본 파일은 32 MiB까지 지원합니다. 이력을 자동 삭제하지 않으며 한도 초과 시 저장을 거절합니다. 대규모 장기 사용의 성능은 미검증입니다.

## 잠금 복구

쓰기 중 프로세스가 강제 종료되면 `data/.writer-lock`이 남을 수 있습니다. 자동으로 오래된 잠금을 지우지 않습니다.

1. 서버와 기록 CLI를 모두 종료합니다.
2. `.writer-lock/owner.json`의 PID와 시간을 확인하고 해당 쓰기 프로세스가 더 이상 실행되지 않는지 확인합니다.
3. `journal.json`을 별도 백업하고 파일이 읽히는지 `cli.mjs read`로 확인합니다.
4. `.writer-lock` 폴더를 운영체제 휴지통으로 옮긴 뒤 다시 실행합니다. 다른 프로세스가 쓰고 있다면 이 작업을 하지 않습니다.

## 저장소 변경 대응

앱의 고정 ID와 현재 폴더는 별도입니다. 앱 이름이나 폴더를 바꾸면 앱 정보 수정에서 연결만 갱신합니다. README와 정해진 개발 문서가 없으면 연결 확인 필요를 표시합니다. 임의 파일과 심볼릭 링크는 문서 조회 대상으로 사용하지 않습니다.

새 앱을 등록하거나 기존 앱을 사용 중단으로 바꾸더라도 이전 기록을 삭제하지 않습니다. 앱 폴더 이름을 스캔해서 다른 앱으로 자동 등록하지 않습니다. 기록을 불러올 수 없으면 초기 상태로 덮지 않고 오류를 표시합니다.

## 검사

이 앱 폴더에서 실행합니다.

```sh
node --test test/*.test.mjs
```

별도 프로세스의 CLI와 로컬 HTTP 서버를 실제로 사용합니다. 포트 실행을 막는 환경에서는 권한이 필요합니다. [검증 기록](docs/verification.md)에 실행 환경과 미검증 범위를 남깁니다.
