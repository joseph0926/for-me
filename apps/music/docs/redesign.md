# 화면 재설계 (2026-11-28)

- "파일이 많을때 특정 카테고리로 찾아서 모으기(재생목록에 넣기위해? 등등..)가 너무 불편합니다."
- "/today-ref-use 로 디자인 처음부터 다시 시작"

오늘의레퍼런스의 [기능 유지, 전면 재설계 절차](../../today-ref/docs/refine.md#d-기능-유지-전면-재설계)를 따랐습니다. 이 문서는 그 절차가 남기라는 행동 목록과 전후 결과입니다. 정체성과 사용자 결정은 [README의 UI 결정](../README.md#ui-결정)에 있습니다.

## 새 화면 켜기

새 화면은 `android/src/main/java/dev/forme/music/redesign`에 있고, Gradle 속성을 줄 때만 켜집니다. 속성이 없으면 옛 화면(`ui` 패키지의 `MusicApp`)이 그대로 나옵니다. 옛 화면을 새 화면으로 바꿔 끼우는 결정은 사용자가 합니다.

```bash
./gradlew --no-daemon -Pmusic.redesign=true :android:assembleDebug
```

두 화면은 같은 데이터(재생 목록, 이어듣기, 직접 추가한 곡)를 씁니다. 가상 기기에서 새 화면 빌드와 옛 화면 빌드를 번갈아 덮어 설치해도 재생 목록 네 개와 이어듣기 곡이 그대로 남았습니다.

## 바뀐 것

- **묶어 찾기:** 보관함 맨 위 네 바로가기(폴더, 가수, 채널, 추가한 달)에서 묶음 목록으로 들어가고, 목록 맨 위에서 기준을 바로 바꿉니다. 묶음 상세는 큰 묶음 커버, 곡 수와 총 길이, 모두 담기, 셔플, 재생입니다.
  - 가수는 태그 제목의 "가수 - 곡명" 앞부분을 먼저 보고, 없으면 파일 이름의 같은 꼴을 봅니다. 사용자 음악은 파일 이름에 곡명만 있고 태그 제목에 가수가 있기 때문입니다([형식 확인](verification.md#2026-11-28-사용자-음악-파일의-형식-확인)). 앞의 "[LIVE]" 같은 괄호 머리말은 뺍니다. 사용자는 "파일 이름의 가수"를 골랐는데, 이렇게 태그 제목을 먼저 보는 것은 AI 해석이라 사용자 확인이 필요합니다.
  - 채널은 태그의 아티스트입니다. 폴더는 저장소 안 경로이고, 파일 선택기로 직접 추가한 곡은 "직접 추가한 곡"으로 모입니다.
- **여러 곡 담기:** 곡을 길게 누르거나 곡 탭의 '고르기'로 고르기를 시작합니다. 맨 위에 고른 수와 '모두 고르기', 아래에 재생 목록에 담기, 다음에 재생, 대기열에 추가 막대가 나옵니다. 고른 순서대로 담고, 묶음째 담을 때는 재생 목록에 이미 있는 곡을 건너뛰고 몇 곡을 건너뛰었는지 알립니다. 곡 하나를 메뉴로 담을 때는 예전처럼 겹쳐 넣습니다.
- **묶음째 재생 목록 만들기:** 묶음 상세의 담기 단추에서 '새 재생 목록'을 고르면 묶음 이름이 미리 들어 있습니다.
- **속지 정체성:** Wanted Sans 서체, 커버 색이 번지는 재생 화면, 손잡이로 끄는 재생 목록과 대기열, 큰 커버가 있는 상세, 상자 없는 네 칸 바로가기, 탭 바로 위 평평한 미니 플레이어와 진행선. 셔플과 반복은 재생 화면이 아니라 대기열 아래에 있습니다(속지와 같음).
- **대기열:** 셔플 중에도 실제로 다음에 나올 순서로 보입니다. 셔플 중에는 목록 순서와 재생 순서가 달라 끌기 손잡이를 숨기고 메뉴의 위로, 아래로, 빼기만 둡니다. 옛 화면처럼 이미 지난 곡도 '지난 곡'으로 보이고 눌러서 돌아갈 수 있습니다.

## 레퍼런스

- 재생 화면, 미니 플레이어, 재생 목록 상세, 대기열, 보관함: 완성작 [속지](../../today-ref/works/2026-11-28-music/README.md)(`2026-11-28-music`)
- 묶어 찾기와 여러 곡 고르기: 수집 주제 `2026-11-28-music-gather`(완성작 없음, 스토어 정지 화면 10개). 아래 동작 막대(Musicolet, YouTube Music 웹), 왼쪽 동그라미 고름 표시(멜론), 묶음 상세의 "곡 수, 총 길이"와 재생, 셔플(Auxio, YouTube Music, Poweramp), 아이콘 바로가기 줄(Retro Music, 멜론)을 참고했습니다. 여러 곡 고른 상태를 Android에서 직접 보여 준 레퍼런스는 하나뿐이고, "재생 목록에 모두 담기"를 보여 준 레퍼런스는 없었습니다.

## 확인 중 고친 것

- 대기열이 길면 셔플과 반복이 목록 끝으로 밀려 보이지 않았습니다. 재생바 위에 고정했습니다.
- 그림이 없는 노란 커버의 재생 화면 바탕이 검정을 섞어 탁한 올리브색이 됐습니다. 색상과 채도를 지키고 밝기만 낮추며, 노랑 계열은 주홍 쪽으로 옮깁니다.
- '다음에 재생'과 '재생 목록에 담기' 아이콘이 거의 같았습니다. 다음에 재생은 재생 세모를 위쪽 줄에, 대기열에 추가는 아래쪽 줄에 둡니다(속지와 같은 방법).
- 1분이 안 되는 재생 목록의 길이가 "0분"으로 나왔습니다. 1분 미만은 초로 보입니다.
