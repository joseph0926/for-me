# 이미지를 먼저 보고 필요할 때 편집하기

2026-11-24. Finder에서 사진을 열어 확인하거나 screen-gif로 녹화한 움직임을 바로 보는 상황을 기준으로 조사했다.

## 보기와 편집

정지 이미지는 보기가 기본이다. 편집을 누르면 도구를 펼치고, 보기로 돌아가면 편집 중인 문서에서 도구와 선택 테두리만 접는다. 사진과 메모의 위치, 자른 범위, 되돌리기 기록은 같은 문서가 소유한다. 보기로 전환하는 동작은 파일을 쓰지 않는다. 결과를 파일로 만들 때 사용자가 복사본 저장을 누른다. 편집한 사진을 다른 파일로 교체할 때는 보기에서도 확인을 받는다.

## GIF 재생 조사

- 2D 캔버스에 애니메이션 이미지를 그리면 브라우저는 기본 이미지 또는 첫 프레임을 사용한다. Screen Note의 편집 화면은 Konva 캔버스를 사용하고, 복사와 저장은 표시를 합성해 PNG 한 장을 만든다. 파일 선택기에 GIF만 추가하면 움직임을 볼 수 없다. [HTML 표준](https://html.spec.whatwg.org/multipage/canvas.html#image-sources-for-2d-rendering-contexts), [편집 결과를 PNG로 만드는 코드](../src/copy.ts)
- GIF 보기는 웹뷰의 이미지 요소에 원본 데이터를 전달한다. 재생 간격과 반복 횟수는 GIF와 웹뷰가 처리한다. 캔버스에서 프레임마다 표시를 합성하는 방식은 별도 디코딩과 다시 그리기가 필요하다. 이번 범위는 재생이므로 라이브러리를 추가하지 않는다. [HTML 이미지 표준](https://html.spec.whatwg.org/multipage/images.html), [Konva의 캔버스 GIF 예제](https://konvajs.org/docs/sandbox/GIF_On_Canvas.html)
- Finder의 다음으로 열기에 GIF를 추가할 때는 macOS의 기존 GIF 형식에 대해 뷰어 역할을 선언한다. PNG, JPEG, WebP는 편집기 역할을 유지한다. 앱 선택, 끌어놓기, 붙여넣기와 Finder에서 받은 파일에 같은 보기 방식을 적용하려면 이름이나 클립보드가 제공하는 형식만으로 판별하지 않고 GIF 데이터의 시작 부분을 확인한다. [Apple GIF 형식](https://developer.apple.com/documentation/uniformtypeidentifiers/uttype-swift.struct/gif), [Tauri 파일 연결 설정](https://v2.tauri.app/reference/config/#fileassociations)

## 오늘의레퍼런스 적용

완성작 **손질**에서 바위 해안 사진을 열고 자르기와 펜으로 전환했다. 1060 × 760 창에서 저장 버튼은 머리줄 오른쪽 끝에서 12px 떨어져 있었다. 완성작에는 보기 전용 모드나 GIF 재생 화면이 없어 이 두 상태는 Screen Note의 사용 흐름에서 설계했다. [완성작의 구성과 실행 방법](../../today-ref/works/2026-11-23-image-editor/README.md)

| 완성작의 부분 | 대상 화면의 자리 | 옮기는 방식 | 완성작 값 | 대상 값 | 확인 방법 |
|---|---|---|---|---|---|
| r3 사진과 편집 조작 | 사진, 머리줄, 편집 도구 | 편집에서만 도구와 설정을 보이고 주요 동작을 오른쪽에 배치 | 오른쪽 저장, 사진 위 자르기 안내선 | 보기에서 편집, 편집에서 오른쪽 복사본 저장과 자르기 안내선 | 실행 |
| r1 조정 패널 | 없음 | 적용하지 않음 | 빛과 색 슬라이더 | 해당 없음 | 코드 |
| r2 원본 비교 | 없음 | 적용하지 않음 | 끌어서 나누는 비교 막대 | 보기는 현재 편집 결과 한 장 | 코드 |
| r5 필터 목록 | 없음 | 적용하지 않음 | 사진 아래 필터 썸네일 | 해당 없음 | 코드 |

검증할 때는 같은 이미지에서 자르거나 표시한 뒤 보기, 편집, 되돌리기를 이어서 확인한다. GIF에서는 파일이 열렸다는 응답과 실제로 화면의 픽셀이 시간에 따라 바뀌는지를 따로 확인한다.
