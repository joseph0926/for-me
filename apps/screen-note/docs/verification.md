## 0.2.0 실행 시간과 CPU, 메모리 사용량

2026-11-23, Apple M4 Pro, 메모리 48GB, macOS 27.2.1. 위의 0.2.0 macOS 빌드로 첫 화면을 측정했다. 버튼 준비 시점과 편집 작업은 같은 배포용 화면 코드에 시간 기록과 자동 입력을 추가한 빌드에서 측정했다.

### 앱을 열 때

운영체제 캐시를 비우지 않고 매번 새 프로세스를 실행했다. 배포 빌드 9회에서 실행 요청부터 창 표시까지 중앙값은 279ms였다. 별도 측정 빌드의 기본 화면 9회에서는 이미지 열기 버튼의 입력 처리까지 376ms였다. 앱 본체 진입부터 WebKit이 화면 코드를 시작하기까지 238ms, 그 뒤 버튼 입력 처리까지 63ms였다. 첫 화면에서 배경 이미지를 뺀 조건은 367ms, 글꼴을 뺀 조건은 385ms였다(각 9회, 버튼 기준). [실행 회차별 측정값](0.2.0-startup.csv)

배포 빌드 3회에서 실행 후 첫 1초의 CPU는 평균 54.75%, 메모리는 최고 321MiB였다. 실행 후 3~6.8초 동안 첫 화면에 두면 CPU 0.55%, 메모리 109MiB였다. 이 중 앱 본체는 약 33MiB였다. 각 수치는 회차별 결과의 중앙값이다.

| 펜으로 다섯 획 그리기 | 45% | 269MiB | 45% | 299MiB |
| 복사용 PNG 생성 | 95% | 319MiB | 99% | 773MiB |
| PNG 생성 후 2.5~4.5초 대기 | 1.13% | 161MiB | 1.32% | 472MiB |

- 앱 본체와 이 앱에 속한 WebKit의 화면 처리, 그래픽, 네트워크 프로세스를 합산했다. CPU는 코어 하나를 100%로 본 구간 평균이다. 메모리는 macOS가 각 프로세스에 부과한 메모리를 약 25ms 간격으로 읽었다. 작업 중에는 관측 최고값, 대기 중에는 중앙값을 구한 뒤 각 조건에서 완료한 3회의 중앙값을 표에 실었다. 자동 입력용 파일을 전달하면서 생긴 메모리도 포함될 수 있다.
- PNG 생성 시간은 작은 사진 61ms, 큰 사진 424ms였다. 편집 예비 측정에서 사진 입력이 실패한 1회와 작은 사진에서 제한 시간 안에 완료 신호가 오지 않은 2회는 집계에서 제외했다. 시작 시간을 세분한 별도 실험에서도 완료 신호를 받지 못한 회차는 실행 시간 CSV에 표시했다.

### 평가와 다음 검증

이 Mac에서 첫 화면은 CPU 1% 미만으로 안정됐고, 실행 시간에서 가장 길었던 구간은 앱 본체가 시작된 뒤 WebKit이 화면 코드를 실행하기까지였다. 두 해상도에서 펜 입력의 CPU는 비슷했다. 실제 펜의 입력 지연과 프레임 간격은 측정하지 않았다.

개선 우선순위는 원본 크기로 사진과 주석을 합쳐 복사용 PNG를 만드는 구간이다. 큰 사진에서 메모리가 773MiB까지 올랐고, 생성 후 2.5~4.5초에도 사진을 열어 둔 상태보다 약 320MiB 많았다. 다음 실험은 같은 큰 사진을 여러 번 복사한 뒤 문서를 닫는 순서로 진행하고, 매번 대기 중 메모리가 일정 수준에 머무는지 확인한다. 장시간 메모리 회수, 반복 복사에 따른 누적, Windows 동작은 이번 측정 범위 밖이다. [PNG 생성 코드](../src/copy.ts)
